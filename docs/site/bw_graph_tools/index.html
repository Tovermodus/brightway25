bw_graph_tools

Graph traversal for the technosphere supply chain: given an already-solved bw2calc.LCA result, walks the network of activities consuming each other's products to find which parts of the supply chain drive the score — plus standalone shortest-path utilities.

Installed at .venv/lib/python3.11/site-packages/bw_graph_tools/, version 0.10 (PyPI bw_graph_tools). Upstream repo: brightway-lca/bw_graph_tools.

Typical usage

import bw2data as bd
from bw2calc import LCA
from bw_graph_tools import GraphTraversalSettings, NewNodeEachVisitGraphTraversal

# an already-registered activity and LCIA method
activity = bd.get_node(database="my-db", name="steel production")
lca = LCA({activity: 1}, method=("my", "method"))
lca.lci()
lca.lcia()

settings = GraphTraversalSettings(cutoff=1e-2, max_calc=500)
gt = NewNodeEachVisitGraphTraversal(lca, settings)
gt.traverse()

for node in sorted(gt.nodes.values(), reverse=True)[:5]:
    print(node.depth, node.cumulative_score, node.activity_datapackage_id)

for flow in sorted(gt.flows, reverse=True)[:5]:
    print(flow.score, flow.flow_datapackage_id)

Where to look

How do I run a graph traversal?

Build a solved bw2calc.LCA (.lci() + .lcia()), then NewNodeEachVisitGraphTraversal(lca, GraphTraversalSettings(...)).traverse() and read the nodes / edges / flows properties (graph_traversal/base.py, graph_traversal/new_node_each_visit.py).

What fields does a result node/edge/flow have?

graph_traversal/graph_objects.py — Node (cumulative_score vs. direct_emissions_score, depth, terminal), Edge (consumer_*/producer_* indices and unique ids), Flow (per characterized-biosphere-flow score).

How do cutoffs / depth limits / calculation budget work?

graph_traversal/settings.py GraphTraversalSettings fields (cutoff, biosphere_cutoff, max_calc, max_depth, min_coverage_fraction), enforced inside new_node_each_visit.py's _traverse() / traverse().

How does it identify the reference production exchange in the matrix?

matrix_tools.py guess_production_exchanges(), a heuristic chain from gpe_zeroth_heuristic (explicit modeller flag, authoritative) through gpe_fifth_heuristic; raises errors.UnclearProductionExchange when none apply. AssumedDiagonalGraphTraversal skips this and assumes the diagonal instead.

How do I find just the single most important path between two activities?

graph_traversal_utils.py get_path_from_matrix() / path_as_brightway_objects(), built on matrix_tools.to_normalized_adjacency_matrix() (log-transformed, sign-flipped so a shortest-path algorithm finds the path of greatest multiplicative flow) and shortest_path.get_shortest_path().

How does traversal avoid re-solving the linear system for repeated activities?

graph_traversal/utils.py CachingSolver (PARDISO fast path in _unit_scores_pardiso, iterative fallback in _unit_scores_iterative), wired in via GraphTraversalSettings.caching_solver.
