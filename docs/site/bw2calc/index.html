bw2calc

The LCA calculation engine of Brightway 2.5 — turns bw_processing datapackages (built from bw2data) into scipy sparse matrices via matrix_utils, then solves them: demand → supply vector → inventory → characterized impact score. This is where the actual "life cycle assessment" math happens; everything upstream just prepares data for it, and bw2analyzer post-processes what it produces.

Typical usage

A runnable, verified version of this pattern — with a real biosphere flow, a registered Method, and captured output — is Example 3 on the Examples page. For running many impact categories/functional units together, or a stochastic Monte Carlo run, see the bw2calc examples section (Examples 4 and 5) — described under Worked examples below.

import bw2data as bd
import bw2calc as bc

bd.projects.set_current("my project")
activity = bd.get_node(name="some activity")

lca = bc.LCA({activity: 1}, method=("some", "method"))
lca.lci()          # solve technosphere -> supply array -> biosphere flows (lca.inventory)
lca.lcia()         # apply characterization matrix -> lca.score

print(lca.score)

# Re-run with a different demand or method without rebuilding everything:
lca.redo_lcia({activity: 2})
print(lca.score)

# Tidy results
df = lca.to_dataframe()

Where to look

How does the technosphere actually get solved?

lca_base.py LCABase.solve_linear_system() and LCABase.lci() drive the process; lca.py LCA builds the concrete technosphere/biosphere matrices via matrix_utils.MappedMatrix and calls the chosen solver (pypardiso, umfpack, or scipy.sparse.linalg.spsolve/factorized, selected in __init__.py).

How does Monte Carlo uncertainty work?

Simplest path: plain LCA(demand, method, use_distributions=True, seed_override=...) — since LCABase(Iterator), every next(lca) re-samples each uncertain matrix entry and recomputes lca.score (see Example 5). For a large system where only a foreground subset is stochastic, partitioned_lca.py PartitionedMonteCarloLCA pre-solves the static background once and samples only the stochastic partition per iteration. Both draw from stats_arrays' distributions, stored on disk via bw_processing's UNCERTAINTY_DTYPE. Exchange-level uncertainty is set in bw2data before .save(), e.g. exc["uncertainty type"] = 3; exc["loc"] = 1.8; exc["scale"] = 0.2 (field name has a literal space; the integer id matches stats_arrays.UncertaintyType, normal == 3).

How do multiple methods / functional units run together efficiently?

multi_lca.py MultiLCA (shared factorized technosphere across many demands and methods) and method_config.py MethodConfig; for score-only batches see fast_scores.py FastScoresOnlyMultiLCA. bd.get_multilca_data_objs(functional_units, method_config) (bw2data/compat.py) builds the matching data_objs — the MultiLCA analogue of prepare_lca_inputs(). After mlca.lci(); mlca.lcia(), MultiLCA.scores is a dict keyed (impact_category_tuple, functional_unit_name) → score. See Example 4.

Where do the LCA-specific exceptions come from?

errors.py — all subclass BW2CalcError, e.g. OutsideTechnosphere, NonsquareTechnosphere, MalformedFunctionalUnit, EmptyBiosphere, CyclicDependencyGraph.

How do matrix row/column indices map back to database ids?

dictionary_manager.py DictionaryManager / ReversibleRemappableDictionary, exposed on an LCA instance as lca.dicts.activity, lca.dicts.product, lca.dicts.biosphere.

How do I get results out as a table?

lca.py LCA.to_dataframe() returns a tidy pandas.DataFrame of the (optionally characterized) inventory.

Related modules

bw2data — supplies the activities/exchanges and processed datapackages that bw2calc consumes.
bw_processing — the on-disk datapackage format bw2calc reads (technosphere, biosphere, characterization arrays).
matrix_utils — builds those datapackages into the live scipy matrices that lca_base.py solves.
stats_arrays — uncertainty distributions sampled for use_distributions=True and PartitionedMonteCarloLCA.
bw2analyzer — consumes finished LCA objects for contribution analysis and comparisons.
