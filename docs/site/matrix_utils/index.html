matrix_utils

Turns bw_processing datapackages into scipy.sparse matrices — the glue layer between on-disk/in-memory LCA data resources and the matrices bw2calc actually factorizes. Version installed: 0.9.

matrix_utils has no LCA-specific knowledge. It doesn't know what a "technosphere" or "biosphere" matrix is — it just knows how to map arbitrary integer ids to dense matrix indices, merge multiple data sources into one sparse matrix, and advance that matrix through Monte Carlo iterations or scenarios. That semantic meaning is layered on top by bw2calc.

Main classes & entry points

Everything below is exported from the top-level package (see __init__.py __all__):

MappedMatrix

mapped_matrix.py — build one sparse matrix from a list of datapackages targeting the same matrix label.

MappedMatrixDict

mapped_matrix_dict.py — a dict of MappedMatrix objects sharing row/col mapping and a global indexer.

SparseMatrixDict

mapped_matrix_dict.py — dict of plain scipy.sparse matrices; overloads @ for bulk multiplication.

ArrayMapper

array_mapper.py — map arbitrary integer ids to dense 0..n-1 matrix indices.

ResourceGroup

resource_group.py — one datapackage group's data/indices/masks/aggregation logic.

RandomIndexer

indexers.py — seeded RNG (via numpy.random.Generator) producing the next column/sample index.

SequentialIndexer

indexers.py — simple incrementing index, wraps at array width by consumers.

CombinatorialIndexer / Proxy

indexers.py — cartesian product over several max_values; Proxy exposes one dimension of it per resource group.

Typical usage

Building a matrix from one or more bw_processing datapackages, then stepping through Monte Carlo iterations:

from bw_processing import load_datapackage, create_datapackage
from matrix_utils import MappedMatrix

# `packages` is a list of already-loaded bw_processing Datapackage objects,
# each containing one or more resource groups tagged matrix="technosphere_matrix"
mm = MappedMatrix(
    packages=packages,
    matrix="technosphere_matrix",
    use_vectors=True,
    use_arrays=True,
    use_distributions=False,
)

mm.matrix               # scipy.sparse.csr_matrix, ready to use
mm.row_mapper.to_dict()  # {original_row_id: matrix_row_index, ...}

# Advance to the next Monte Carlo iteration / scenario column and refill in place
next(mm)
mm.matrix  # same object, data updated

# Trace elements back to their source datapackage
mm.input_provenance()     # [(datapackage, group_label, (start, end)), ...]
mm.input_raw_indices()    # original ids, aligned with input_data_vector()

Where to look

How does a datapackage row/col id become a matrix row/col index?

ArrayMapper in matrix_utils/array_mapper.py. It dedupes and sorts the input id array, builds a one-column sparse lookup, and exposes map_array() (returns -1 for unmapped ids), plus to_dict()/reverse_dict() for debugging. MappedMatrix.__init__ builds a row and column ArrayMapper automatically unless one is passed in explicitly (used to force alignment with an existing mapping, e.g. reusing a biosphere row mapping when building a characterization matrix).

How do I build a matrix from a set of datapackages?

MappedMatrix.__init__ in matrix_utils/mapped_matrix.py. Flow: filter resource groups down to the requested matrix label (utils.filter_groups_for_packages) → wrap each in a ResourceGroup → build/attach row & column ArrayMappers → assemble an empty scipy.sparse.coo_matrix sized to the mapped dimensions → .tocsr() → rebuild_matrix() to fill in data. Raises AllArraysEmpty unless empty_ok=True.

How does Monte Carlo / scenario iteration work?

matrix_utils/indexers.py defines the indexer types; MappedMatrix.add_indexers (in mapped_matrix.py) picks one indexer per datapackage based on its metadata (combinatorial, sequential, or falls back to a seeded RandomIndexer), shared across all of that package's resource groups. Calling next(mapped_matrix) runs MappedMatrix.__next__ → iterate_indexers() then rebuild_matrix(), which recomputes each group's (row, col, data) via ResourceGroup.calculate().

How do several matrices stay aligned across scenarios (e.g. per-database matrices)?

MappedMatrixDict in matrix_utils/mapped_matrix_dict.py. It forces every MappedMatrix it builds to share the same row_mapper/col_mapper and the same global_indexer, so next(mapped_matrix_dict) advances all of them together. SparseMatrixDict (same file) overloads @ so a dict of matrices can be multiplied against a sparse matrix or another dict in one call, using utils.unroll to merge tuple keys.

What's the difference between a resource group's .row_mapped and .row?

ResourceGroup in matrix_utils/resource_group.py — see the class docstring (top of the file) for a worked example. .row_mapped/.col_mapped are raw datapackage ids run through the ArrayMapper (may contain -1 for unmapped ids); .row/.col are what actually gets inserted into the matrix, after optional intra-group aggregation (sum_intra_duplicates, via aggregation.aggregate_with_sparse) and masking out unmapped or filtered elements.

What exceptions can this package raise?

matrix_utils/errors.py: AllArraysEmpty (no data available to build the requested matrix — message built by utils.handle_all_arrays_empty), EmptyArray (an ArrayMapper got/was asked to map an empty array without empty_ok=True), EmptyInterface (a datapackage interface resource is "dehydrated" and needs rehydrating before use — checked in MappedMatrix.__init__), and NoArrays (defined for API compatibility; not currently raised within this package).

bw_processing — the datapackage format that matrix_utils reads (vectors, arrays, indices, flip/rescale, metadata).
bw2calc — the LCA calculation engine that uses MappedMatrix/MappedMatrixDict to build technosphere, biosphere, and characterization matrices and solve the linear systems.
bw2data — the database layer whose integer node/activity "row ids" are exactly the ids that ArrayMapper maps to matrix row/column indices.
