ecoinvent_interface

Authenticated HTTP client for the ecoinvent LCI database's download API. It logs in against ecoinvent's SSO, then lists and downloads release archives, per-version extra files, reports, and individual process datasets, caching everything on disk. It does not parse the data itself — bw2io reads the files this package downloads and imports them into bw2data.

Typical usage

Authenticate once via Settings, then use EcoinventRelease to discover and download a full release:

from ecoinvent_interface import EcoinventRelease, ReleaseType, Settings, permanent_setting

# one-time: persist credentials to disk (or set EI_USERNAME / EI_PASSWORD env vars)
permanent_setting("username", "my-ecoinvent-username")
permanent_setting("password", "my-ecoinvent-password")

settings = Settings()
release = EcoinventRelease(settings)

print(release.list_versions())            # e.g. ['3.9.1', '3.10', ...]
print(release.list_system_models("3.10")) # e.g. ['cutoff', 'apos', 'consequential']

path = release.get_release(
    version="3.10",
    system_model="cutoff",
    release_type=ReleaseType.ecospold,
)
# path now points at the extracted, locally-cached ecoSpold02 directory

To grab a single dataset instead of a whole release, use EcoinventProcess:

from ecoinvent_interface import EcoinventProcess, ProcessFileType, Settings

process = EcoinventProcess(Settings())
process.set_release(version="3.10", system_model="cutoff")
process.select_process(attributes={
    "name": "electricity production, hydro, pumped storage",
    "reference product": "electricity, high voltage",
    "location": "CH",
})
info = process.get_basic_info()
process.get_file(ProcessFileType.upr, directory=".")

Where to look

"How does login/authentication work?"
core.py — InterfaceBase.__init__ reads credentials from Settings; InterfaceBase.login() and refresh_tokens() talk to ecoinvent's SSO endpoint. The @logged_in / @fresh_login decorators auto-login/refresh before any API call, so you never call them yourself.
Full generated API reference →

Auto-generated from installed docstrings via pdoc (see docs/generate_api_docs.py) — every public class, function and module in ecoinvent_interface, always in sync with what is installed. Not committed to git; built fresh on every deploy.

"Where do downloaded files end up, and how is caching decided?"
storage.py — CachedStorage picks a cache directory (explicit path, Settings.output_path, or a platformdirs default) and tracks what's already downloaded in Catalogue (catalogue.json). _download_and_cache() in core.py is where the actual skip-if-cached / redownload logic lives.
"How do I download a full release archive?"
EcoinventRelease.get_release() in release.py — pass a version string, a system model, and a ReleaseType. It also patches version strings in the extracted XML afterwards via spold_versions.py.
"How do I download just one process/dataset?"
EcoinventProcess in process_interface.py: set_release() → select_process() (by attributes, filename, or dataset_id) → get_file() / get_basic_info() / get_documentation().
"Where does the name/product/location → filename matching happen?"
mapping.py's ProcessMapping builds and caches the lookup table; process_interface.get_cached_mapping() loads it for select_process().
"How are credentials configured, and how do I avoid retyping them?"
settings.py — Settings reads EI_USERNAME, EI_PASSWORD, EI_CLIENT_ID, EI_OUTPUT_PATH env vars or an on-disk secrets store; permanent_setting(key, value) writes a value to that store so future Settings() instances pick it up.
bw2io → uses EcoinventRelease (via import_ecoinvent_release) to fetch release archives before importing them into bw2data.
