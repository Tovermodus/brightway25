Brightway 2.5 — code map

This repository (brightway25) is only a meta-package that pins the Brightway 2.5 dependency stack — see pyproject.toml. The real code for every package below lives on PyPI / GitHub and is installed locally into .venv/lib/python3.11/site-packages/ via pip install -e ".[dev]". These pages map that installed source so you can navigate it without relying on (often stale) upstream docs.

Recreate the source locally with: 
python3 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]"
then open docs/site/index.html in a browser (no server needed — plain file:// links).

Three kinds of docs on this site

Each package below has a handwritten map page (this site) explaining how it fits into the Brightway stack — key files, main classes, call flow — written and updated as questions about the codebase get answered (see this repo's CLAUDE.md). Every card also links to a generated API reference (the "API reference →" links, built with pdoc from each package's actual docstrings): every public class, function, and module, always in sync with whatever version is installed. Generate it locally with python docs/generate_api_docs.py after pip install pdoc (it isn't committed to git — see docs/site/api/ in .gitignore — and is rebuilt automatically on every GitHub Pages deploy, see .github/workflows/pages.yml). It's not just for these 16 packages: the generator auto-discovers any package that has a docs/site/<name>/index.html page and is importable, so adding API docs for another package is just adding its map page (copy an existing one) — no script changes needed. On top of both, the Examples page and tutorials give runnable, verified walkthroughs with real captured output — module pages link into specific examples (and back) via anchored class/function names, so you can go from "what is Database" to "here it is being used" to "here's every method it has" in one click each way.

Architecture — how the pieces fit together

stats_arrays   bw2parameters            (leaf utility libs: uncertainty, formulas)
        \           /
     bw_processing ── matrix_utils ── bw_graph_tools
              \            |              /
               \           |             /
                bw2data (projects, activities, exchanges)
                     |
              multifunctional (allocation, sits on top of bw2data)
                     |
                  bw2calc (LCA solving; matrices via matrix_utils)
                     |
                  bw2analyzer (post-processing of bw2calc results)

Import / export side (independent of the calc stack, writes into bw2data):
  bw_simapro_csv, ecoinvent_interface, bw_migrations,
  randonneur, randonneur_data, mrio_common_metadata  ──►  bw2io  ──►  bw2data
