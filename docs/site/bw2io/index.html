bw2io

Import/export for Brightway: turns ecospold1/2, SimaPro CSV, Excel/CSV, EXIOBASE and openLCA JSON-LD data into bw2data databases and LCIA methods (and back out to CSV/Excel/Matlab/GEXF/archives) via an extract → apply-strategies → write pipeline.

Installed at .venv/lib/python3.11/site-packages/bw2io/, version 0.9.17 (PyPI bw2io>=0.9.6). Upstream repo: brightway-lca/bw2io.

Import pipeline architecture

Every format follows the same three-stage shape:

extractor.extract(filepath, ...)             # extractors/*.py — raw file -> plain dicts/lists
        │
        ▼
Importer.__init__ builds self.strategies      # importers/*.py — ordered list of strategy funcs
        │
        ▼
importer.apply_strategies()                   # importers/base.py ImportBase — runs each,
        │                                      #   logs to self.applied_strategies, catches
        │                                      #   StrategyError and prints (doesn't abort)
        ▼
importer.statistics() / .match_database(...)  # importers/base_lci.py LCIImporter — check /
        │                                      #   fix unlinked exchanges
        ▼
importer.write_database() / .write_methods()  # bw2data.Database(name).write(data)

Concretely: ImportBase (importers/base.py) owns apply_strategy/apply_strategies and the .unlinked property. LCIImporter (importers/base_lci.py) extends it for inventory data with write_database(...), match_database(db_name=None, fields=None, relink=False, ...) and statistics(...). LCIAImporter (importers/base_lcia.py) is the equivalent for characterization factor data, adding write_methods(...). Format classes like SingleOutputEcospold2Importer and SimaProCSVImporter just wire up an extractor plus a hand-picked, ordered list of strategy functions in __init__ — that list is the format-specific documentation of what quirks need fixing.

A strategy is a plain function data -> data (sometimes partially bound, e.g. functools.partial(migrate_datasets, migration="default-units")), living in strategies/*.py. A migration (migrations.py Migration) is reusable rename/unit lookup data stored per-project and applied by the migrate_datasets/migrate_exchanges strategies — think of migrations as data, strategies as the code that applies them.

Typical usage

import bw2data as bd
import bw2io as bi

bd.projects.set_current("my-project")

# --- ecoinvent release (downloads via ecoinvent_interface) ---
# do NOT run bw2setup() first -- import_ecoinvent_release sets up its
# own version-matched biosphere and LCIA methods
bi.import_ecoinvent_release(
    version="3.9.1",
    system_model="cutoff",
    username="XXX",
    password="XXX",
)

# --- SimaPro CSV export ---
bd.projects.set_current("another-project")
bi.bw2setup()  # default biosphere3 + LCIA methods + core migrations

sp = bi.SimaProCSVImporter("my_export.csv", name="my-simapro-db")
sp.apply_strategies()
sp.statistics()          # prints dataset/exchange/unlinked counts
sp.match_database(fields=["name", "unit", "location"])
if sp.all_linked:
    sp.write_database()

Where to look

How does a SimaPro CSV import work end to end?

importers/simapro_csv.py SimaProCSVImporter.__init__ calls extractors/simapro_csv.py SimaProCSVExtractor.extract() to parse the raw CSV, then builds self.strategies (name/geo splitting, unit fixes, biosphere normalization, technosphere linking via link_technosphere_based_on_name_unit_location). Call .apply_strategies() then .write_database(). The newer importers/simapro_block_csv.py SimaProBlockCSVImporter instead delegates all CSV parsing to the external bw_simapro_csv package (SimaProCSV.to_brightway()) and only runs Brightway-side linking strategies afterward — prefer this path for new code (requires multifunctional installed).

How does an ecoinvent import work?

ecoinvent.py import_ecoinvent_release(version, system_model, username, password, ...) is the one-call entry point: it authenticates and downloads the release via ecoinvent_interface, then internally drives importers/ecospold2_biosphere.py Ecospold2BiosphereImporter (biosphere database) and importers/ecospold2.py SingleOutputEcospold2Importer (LCI database, using extractors/ecospold2.py Ecospold2DataExtractor, which can multiprocess XML parsing), plus LCIA method import.

What is a "strategy" and how is it applied?

A plain data -> data function in strategies/*.py, re-exported from strategies/__init__.py. importers/base.py ImportBase.apply_strategy calls one, appends its name to self.applied_strategies, and catches (prints, doesn't raise) StrategyError; apply_strategies runs the whole ordered self.strategies list. Each importer's __init__ builds its own tailored list.

How do I check/fix unlinked exchanges after applying strategies?

ImportBase.unlinked (property, unique unlinked exchanges), importers/base_lci.py LCIImporter.statistics() (prints counts) and .match_database(db_name=None, fields=None, relink=False, ...) (link against another written database, or self-match). unlinked_data.py UnlinkedData/unlinked_data persists a project-level log.

How does data actually get written into bw2data?

importers/base_lci.py LCIImporter.write_database(data=None, delete_existing=True, backend=None, activate_parameters=False, db_name=None, ...) validates (WrongDatabase, NonuniqueCode in errors.py) then calls bw2data.Database(db_name).write(data). LCIAImporter.write_methods() (importers/base_lcia.py) is the LCIA equivalent.

How is EXIOBASE / MRIO data handled?

extractors/exiobase.py (Exiobase3MonetaryDataExtractor), importers/exiobase3_monetary.py (Exiobase3MonetaryImporter) and importers/exiobase3_hybrid.py (Exiobase3HybridImporter), strategies/exiobase.py. __init__.py's exiobase_monetary() downloads a specific EXIOBASE release zip and drives Exiobase3MonetaryImporter end to end; the resulting large database typically uses bw2data's backends/iotable/ matrix-native backend.

Where do the default biosphere3 flows and LCIA methods come from?

__init__.py create_default_biosphere3() runs importers/ecospold2_biosphere.py Ecospold2BiosphereImporter; create_default_lcia_methods() by default fast-paths by loading the pre-baked data/lcia/lcia_39_ecoinvent.zip JSON archive directly, or falls back to importers/ecoinvent_lcia.py EcoinventLCIAImporter when shortcut=False. bw2setup() runs both plus create_core_migrations().

How do I export a database out of Brightway?

export/csv.py write_lci_csv, export/excel.py write_lci_excel/lci_matrices_to_excel, export/matlab.py lci_matrices_to_matlab, export/gexf.py DatabaseToGEXF (Gephi graph export). For a full round-trippable archive of any bw2data DataStore object, use package.py BW2Package.export_obj(...) / BW2Package.import_file(...) instead.

Related modules

bw2data — bw2io's write target: every importer ultimately calls bw2data.Database(...).write(...) / writes an LCIA Method.
bw_simapro_csv — parses SimaPro CSV exports for the newer SimaProBlockCSVImporter, replacing bw2io's own extractors/simapro_csv.py parser.
ecoinvent_interface — handles ecoinvent authentication and file downloads for ecoinvent.py import_ecoinvent_release.
bw_migrations — related migration-data tooling alongside bw2io's own migrations.py.
randonneur — structured data-patch format used for some of bw2io's bundled migration/renaming datasets.
mrio_common_metadata — shared metadata conventions for MRIO/EXIOBASE-style databases that bw2io's exiobase importers produce.
multifunctional — required for SimaProBlockCSVImporter and multi-output allocation handling.
