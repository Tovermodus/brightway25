bw_simapro_csv

A low-level, standalone parser for SimaPro's proprietary CSV export format (processes, LCIA methods, or product stages). Reads the file's header, splits it into logical "blocks", and turns each block's raw lines into clean Python dicts/lists — numbers, dates, formulas, uncertainty distributions, units, and flows. It knows nothing about bw2data; bw2io's SimaProCSVImporter wraps this package's output to build bw2data-compatible datasets.

Installed at .venv/lib/python3.11/site-packages/bw_simapro_csv/, version 0.4.3 (PyPI bw_simapro_csv). Built on bw2parameters (formula evaluation), stats_arrays (uncertainty distribution types), pydantic (header validation), ftfy (mojibake repair), and loguru (structured logging to a per-run log directory).

Main classes & entry points

SimaProCSV

main.py — constructor SimaProCSV(path_or_stream, encoding="sloppy-windows-1252", database_name=None, ...). Reads the header, splits the file into blocks (get_next_block()), resolves parameters/uncertainty (resolve_parameters()), and normalizes units. Iterable over its parsed .blocks; exposes .header and .to_brightway().

SimaProCSVType

header.py — str enum: processes, methods, stages. Read from SimaProCSV.header["kind"]; controls which post-processing steps run.

SimaProCSVBlock

blocks/base.py — base class for every block parser. Subclasses set self.parsed (usually a list[dict]) in __init__; EmptyBlock is the sentinel for a block with no content.

Process

blocks/process.py — the central block class: one LCI process, with metadata plus sub-blocks for products, technosphere edges, elementary flows, waste, and local parameters. Methods resolve_local_parameters(), supplement_biosphere_edges(), check_waste_production_model_consistency().

GenericBiosphere / GenericUncertainBiosphere

blocks/generic_biosphere.py — substance/elementary-flow definitions (end-of-file lists) and their uncertain, amount-bearing use inside a process, respectively.

Method / ImpactCategory

blocks/method.py, blocks/impact_category.py — LCIA method metadata and per-substance characterization factors.

Typical usage

from pathlib import Path
from bw_simapro_csv import SimaProCSV, SimaProCSVType

# Parse a SimaPro CSV process export
simapro_csv = SimaProCSV(Path("my_export.csv"), database_name="my project")

print(simapro_csv.header["kind"])   # SimaProCSVType.processes
print(len(simapro_csv.blocks))      # number of parsed top-level blocks

# Iterate over parsed blocks (Process, Units, DatabaseInputParameters, ...)
from bw_simapro_csv.blocks import Process

for block in simapro_csv:
    if isinstance(block, Process):
        print(block.parsed["metadata"]["Category type"])
        print(list(block.blocks))          # e.g. ["Products", "Materials/fuels", ...]
        print(block.blocks["Products"].parsed)

# Or go straight to a bw2io-flavoured dataset dict (process exports only)
if simapro_csv.header["kind"] == SimaProCSVType.processes:
    data = simapro_csv.to_brightway(separate_products=True, shorten_names=True)

Where to look

How is the file split into blocks, and what happens when End markers are missing?

main.py SimaProCSV.get_next_block(), dispatch tables CONTROL_BLOCK_MAPPING/INDETERMINATE_SECTION_HEADERS; csv_reader.py BeKindRewind.rewind() implements the one-line look-ahead needed because some files never use the End convention (raises errors.IndeterminateBlockEnd if that makes a section ambiguous).

How is a SimaPro "block" (Process, Method, Units, …) actually parsed?

blocks/base.py SimaProCSVBlock defines the contract (populate self.parsed). The richest example is blocks/process.py Process.__init__, which uses utils.get_key_multiline_values() to separate metadata key/value pairs from named sub-blocks, dispatched via its own BLOCK_MAPPING.

How are units and unit conversions handled?

blocks/units.py Units parses the file's unit → reference-unit + conversion-factor table; units.py normalize_units() applies it afterwards to every exchange's amount/formula/uncertainty distribution across all Process blocks.

How are uncertainty distributions mapped to stats_arrays?

uncertainty.py distribution(amount, kind, field1, field2, field3, ...) converts SimaPro's Undefined/Lognormal/Normal/Triangle/Uniform columns into a stats_arrays-compatible dict, with parameter sanity checks that fall back to undefined_distribution(). Called from blocks/process.py Process.resolve_local_parameters() once each exchange's numeric amount is known.

How are formulas (including SimaPro-specific syntax) parsed and evaluated?

parameters.py prepare_formulas()/fix_iff_formula()/fix_leading_zero_formula() clean up raw formula strings; FormulaSubstitutor renames variables across parameter scopes; actual evaluation uses bw2parameters.Interpreter/ParameterSet, driven from main.py SimaProCSV.resolve_parameters() (project/database scope) and blocks/process.py Process.resolve_local_parameters() (per-process scope).

How does this become a bw2data-ready dataset?

main.py SimaProCSV.to_brightway() calls brightway.py lci_to_brightway() — but in practice bw2io.importers.simapro_csv.SimaProCSVImporter is the usual entry point, wrapping a SimaProCSV instance to build full bw2data-compatible activities and exchanges.

No worked example is provided for this package on the Examples page — bw2io ships no bundled SimaPro CSV fixture to run against without a real SimaPro export. Example 8 (ExcelImporter) demonstrates the same extract → strategies → statistics shape against a format bw2io does bundle a fixture for.
