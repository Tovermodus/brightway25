Tutorial: create your own empty database

How to create a fresh, empty bw2data database in a project, ready for you to fill with activities and exchanges yourself.

Everything here uses the real installed bw2data API (.venv/lib/python3.11/site-packages/bw2data/), verified by running it. See the bw2data module map for the full picture of how this layer fits into Brightway.

1. Pick or create a project

Brightway isolates data into projects — each is its own SQLite database + data directory (bw2data/project.py ProjectManager). A database always lives inside the currently active project, so set that first: 

import bw2data as bd

bd.projects.set_current("my_project")  # created automatically if it doesn't exist yet
print(list(bd.projects))               # sanity check: see all projects on this machine

2. Create the database object and register it

bd.Database(name) (an alias for DatabaseChooser, see bw2data/database.py) returns a SQLiteBackend instance for that name — it does not write anything yet. Call .register() to actually create it in the project's metadata store; this is required before you can write any data (bw2data/backends/base.py SQLiteBackend.register()): 

db = bd.Database("example_db")
db.register()

print("example_db" in bd.databases)  # True — registered in bd.databases (meta.py)
print(len(db))                       # 0 — empty, ready to fill

register() calls self.write({}, searchable=False, signal=False) internally by default (write_empty=True), so after this call you already have a valid, empty, processed database — it has a datapackage on disk that bw2calc could load, it's just empty. You can now add content to it at your own pace.

3. Add activities (nodes)

Create new activities with db.new_activity(code, **kwargs) (an alias for new_node, bw2data/backends/base.py). This builds an in-memory Activity proxy (bw2data/backends/proxies.py) — nothing is written to the database until you call .save() on it: 

activity = db.new_activity(
    code="steel_production",       # unique key within this database; omit for a random UUID
    name="steel production",
    unit="kilogram",
    location="GLO",
    type="process",                 # default node type; see bw2data.labels for other node types
)
activity.save()

4. Give it a production exchange

An activity with no exchanges has nothing to relate its amount to. Most process activities need at least a production exchange pointing to themselves, so that bw2calc knows "1 unit of this activity produces 1 kilogram of steel": 

activity.new_exchange(input=activity.key, amount=1, type="production").save()

Activity.new_exchange(**kwargs) (new_edge in backends/proxies.py) creates an Exchange proxy with output pre-set to this activity's key; again, call .save() to persist it.

5. Add more activities and link them together

Repeat the pattern for inputs, then wire them up with technosphere/biosphere exchanges: 

iron_ore = db.new_node(code="raw_ore", name="iron ore", unit="kilogram", location="GLO", type="product")
iron_ore.save()

activity.new_exchange(input=iron_ore.key, amount=2, type="technosphere").save()

An activity's .key is the (database name, code) tuple used everywhere as a stable reference — exchanges link activities by their key, not by object identity.

6. Look at what you built

print(len(db))          # number of activities now in the database
for act in db:
    print(act, act["unit"], list(act.exchanges()))

Full example, start to finish

import bw2data as bd

bd.projects.set_current("my_project")

db = bd.Database("example_db")
db.register()

steel = db.new_activity(code="steel_production", name="steel production", unit="kilogram", location="GLO")
steel.save()
steel.new_exchange(input=steel.key, amount=1, type="production").save()

iron_ore = db.new_node(code="raw_ore", name="iron ore", unit="kilogram", location="GLO", type="product")
iron_ore.save()
steel.new_exchange(input=iron_ore.key, amount=2, type="technosphere").save()

print(len(db))  # 2

Notes & gotchas

  • Register before writing. db.new_activity(...) works fine before register(), but the database won't show up in bd.databases until it's registered (writing also auto-registers it with write_empty=False if you skip this step, via SQLiteBackend.write()).
  • Nothing is saved without .save(). Both new activities and new exchanges are plain in-memory proxy objects until saved — this is intentional, it lets you build up an activity (set several fields, add several exchanges) before committing it.
  • Bulk-loading instead? If you already have all the data as a Python dict of {(db_name, code): {...dataset...}}, call db.write(data) directly instead of looping new_activity/save calls — it replaces the entire contents of the database in one shot (SQLiteBackend.write(), backends/base.py:675). This is what importers in bw2io do.
  • Delete a database you don't want anymore with del bd.databases["example_db"] or bd.Database("example_db").delete().
  • Processing happens automatically. write() (called by both register() and every activity write path through the ORM signal wiring) rebuilds the bw_processing datapackage backing this database, so an empty database is always immediately consumable by bw2calc.LCA — it will just have no flows.
