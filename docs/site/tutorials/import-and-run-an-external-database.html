Tutorial: import and run an LCA on an external database

Every other tutorial on this page builds its activities and exchanges by hand with db.new_node(...). Real work usually starts from someone else's data instead — here we import a small pre-built dataset with bw2io, inspect what came in, and run bw2calc.LCA against it, the same as you would after importing ecoinvent or a SimaPro export.

Everything here uses the real installed bw2io/bw2calc API (.venv/lib/python3.11/site-packages/bw2io/), verified by running it. It needs no network access or ecoinvent/SimaPro credentials — see the bw2io module map for how the same extract → apply strategies → write pipeline scales up to a real ecoinvent release via bw2io.import_ecoinvent_release(...).

1. What we're importing, and why

bw2io ships a small "Mobility example" dataset as an Excel workbook for its own test suite — two ways of driving 1 km (a combustion car and an electric car), each built from component processes (steel, lithium, electricity), with one biosphere flow (CO₂) and an ("IPCC", "simple") characterization method already wired up. bw2io.add_example_database() (bw2io/data/__init__.py) runs the full import pipeline for us — this is the same shape every bw2io import takes: an ExcelImporter extracts the workbook, a list of strategy functions clean and link it, then .write_database() commits it into bw2data. Reading its source (below) is a good template for writing your own import once you have real data instead of this bundled fixture.

Under the hood this is bi.ExcelImporter(dirpath / "examples" / "sample_parameterized_database.xlsx") followed by .apply_strategies(), .match_database(fields=["name"]), and .write_database(activate_parameters=True) — the exact same extract → apply strategies → write steps as the plain ExcelImporter example, just wrapped in one convenience call because this particular workbook needs a specific strategy list (it also carries parameterized formulas) rather than ExcelImporter's generic 14-strategy default. It also registers the ("IPCC", "simple") method with one characterization factor (CO₂ = 1) — a real import instead sources its method from bw2io.create_default_lcia_methods() or an ecoinvent LCIA archive.

3. See what came in

The result is an ordinary bw2data.Database, indistinguishable from one you built by hand — importing doesn't create a different kind of object, it just fills a normal database up front instead of one activity at a time: 

print(sorted(bd.databases))
print(sorted(bd.methods))

db = bd.Database("Mobility example")
print(len(db), "activities")
for act in sorted(db, key=lambda a: a["name"]):
    print(" ", act["name"], "|", act.get("unit"))

Six process activities (two "driving" functional processes plus their component processes: cars, batteries, electricity, lithium, steel), one biosphere flow (CO₂, itself stored as a node in the same database here — the importer's strip_biosphere_exc_locations strategy is about the exchanges, not about which database the flow node lives in), and one method.

4. Run an LCA on an imported activity

Look an activity up by name with Database.get(**filters) — you didn't create this object, so you don't have a Python reference to it lying around the way you would with new_node. From here on, running the LCA is identical to Your first LCA calculation: 

import bw2calc as bc

driving_combustion = db.get(name="Driving an combustion car")
driving_electric = db.get(name="Driving an electric car")

method = ("IPCC", "simple")

lca = bc.LCA({driving_combustion.key: 1}, method)
lca.lci()
lca.lcia()
print("combustion, 1 km:", lca.score)

lca2 = bc.LCA({driving_electric.key: 1}, method)
lca2.lci()
lca2.lcia()
print("electric,    1 km:", lca2.score)
combustion, 1 km: 0.15490749959371897
electric,    1 km: 0.18248161259647167

Same bc.LCA, same .lci()/.lcia()/.score — the only difference from building your own toy system is that all the activities, exchanges, and the method already existed before you wrote any Python.

Full example, start to finish

import bw2data as bd
import bw2io as bi
import bw2calc as bc

bd.projects.set_current("external-import-tutorial")
bi.add_example_database()

db = bd.Database("Mobility example")
driving_combustion = db.get(name="Driving an combustion car")
driving_electric = db.get(name="Driving an electric car")

method = ("IPCC", "simple")

lca = bc.LCA({driving_combustion.key: 1}, method)
lca.lci()
lca.lcia()
print(lca.score)  # 0.15490749959371897

Notes & gotchas

  • This scales to ecoinvent unchanged in shape. bw2io.import_ecoinvent_release(version, system_model, username, password) (bw2io/ecoinvent.py) runs the same extract → strategies → write pipeline against a downloaded ecoinvent release instead of this bundled Excel file — see the bw2io module map. Don't call bw2io.bw2setup() first when using that path; it builds its own correctly-versioned biosphere.
  • Always check .statistics() before trusting an import. add_example_database() is a convenience wrapper that already calls match_database/write_database for you; writing your own importer, call imp.statistics() after apply_strategies() and inspect any unlinked exchanges before write_database() — see example 8 for what an unlinked exchange looks like and how to spot one.
  • Re-running is safe. add_example_database(overwrite=True) (the default) deletes and rebuilds "Mobility example" each time, so you can experiment freely without accumulating duplicate databases.
  • Importing is independent of the calc stack. As the root CLAUDE.md dependency diagram notes, bw2io only ever writes into bw2data — nothing about how you got a database in (typed by hand vs. imported) affects how bw2calc or bw2analyzer treat it afterwards.
