Tutorial: run a Monte Carlo uncertainty analysis

How to attach uncertainty distributions to exchanges, turn a bw2calc.LCA object into an iterator with use_distributions=True, build up a distribution of scores, and compare two scenarios statistically instead of by a single point estimate.

Everything here uses the real installed bw2calc/stats_arrays/bw2data APIs (.venv/lib/python3.11/site-packages/), verified by running it. See the bw2calc module map for how LCA itself works and the stats_arrays module map for the uncertainty distributions and their integer codes. This tutorial continues from the contribution analysis tutorial's car-assembly system.

1. Build a small system

Same shape as the contribution analysis tutorial: a car assembly process draws on steel production and electricity production, each with its own CO₂/CH₄ emissions. A single point-estimate amount for each biosphere exchange is what every earlier tutorial used — here those amounts become distributions instead of fixed numbers. 

import bw2data as bd

bd.projects.set_current("mc-tutorial")

biosphere = bd.Database("biosphere")
biosphere.register()
co2 = biosphere.new_node(code="co2", name="carbon dioxide", unit="kilogram", type="emission")
co2.save()
ch4 = biosphere.new_node(code="ch4", name="methane", unit="kilogram", type="emission")
ch4.save()

db = bd.Database("example_db")
db.register()

steel = db.new_node(code="steel", name="steel production", unit="kilogram", location="GLO")
steel.save()
steel.new_exchange(input=steel.key, amount=1, type="production").save()

electricity = db.new_node(code="electricity", name="electricity production", unit="kilowatt hour", location="GLO")
electricity.save()
electricity.new_exchange(input=electricity.key, amount=1, type="production").save()

car = db.new_node(code="car", name="car assembly", unit="unit", location="GLO")
car.save()
car.new_exchange(input=car.key, amount=1, type="production").save()
car.new_exchange(input=steel.key, amount=900, type="technosphere").save()
car.new_exchange(input=electricity.key, amount=2000, type="technosphere").save()

2. Attach uncertainty distributions to exchanges

Uncertainty lives on the exchange, as extra fields — "uncertainty type" (note the literal space, it is not uncertainty_type), plus whichever of loc/ scale/shape/minimum/maximum that distribution needs. The integer codes are stats_arrays' UncertaintyType ids — verified from uncertainty_types.py: normal = 3, lognormal = 2. For lognormal, loc is the underlying normal's mean in log-space (mu, i.e. log(median)), not the median itself — confirmed from distributions/lognormal.py random_variables(), which samples numpy.random.lognormal(loc, scale) directly. 

import numpy as np

# steel: CO2 factor ~ Normal(mean=1.8, std=0.2) kg CO2 per kg steel
co2_exc = steel.new_exchange(input=co2.key, amount=1.8, type="biosphere")
co2_exc["uncertainty type"] = 3   # stats_arrays.UncertaintyType.normal
co2_exc["loc"] = 1.8
co2_exc["scale"] = 0.2
co2_exc.save()

# electricity: CO2 factor ~ Normal(mean=0.4, std=0.05) kg CO2 per kWh
co2_elec = electricity.new_exchange(input=co2.key, amount=0.4, type="biosphere")
co2_elec["uncertainty type"] = 3
co2_elec["loc"] = 0.4
co2_elec["scale"] = 0.05
co2_elec.save()

# electricity: CH4 factor ~ Lognormal(median=0.02, sigma=0.3) kg CH4 per kWh
ch4_elec = electricity.new_exchange(input=ch4.key, amount=0.02, type="biosphere")
ch4_elec["uncertainty type"] = 2   # stats_arrays.UncertaintyType.lognormal
ch4_elec["loc"] = np.log(0.02)     # mu = log(median), NOT the median itself
ch4_elec["scale"] = 0.3            # sigma
ch4_elec.save()

The plain amount stays as the deterministic fallback — code that never runs a Monte Carlo iteration (e.g. plain lca.lci(); lca.lcia()) just uses it unchanged. Setting "uncertainty type" only changes behavior when something asks for a sample.

3. Run the Monte Carlo LCA

Register a characterization method as before, then build an LCA with use_distributions=True. That makes the LCA object itself an iterator (it subclasses Iterator, see lca_base.py LCABase): every next(lca) call re-samples every uncertain matrix entry from its distribution and leaves a fresh value in lca.score. seed_override seeds that sampling so the whole run is reproducible. 

import bw2calc as bc

method_key = ("tutorial_method", "gwp")
method = bd.Method(method_key)
method.register(unit="kg CO2-eq")
method.write([(co2.key, 1.0), (ch4.key, 28.0)])   # CH4 = 28x CO2-eq (GWP100)

lca = bc.LCA({car.key: 1}, method_key, use_distributions=True, seed_override=42)
lca.lci()
lca.lcia()

scores = [lca.score]
for _ in range(999):
    next(lca)              # re-samples the technosphere/biosphere/CF matrices
    scores.append(lca.score)

scores = np.array(scores)
print(f"iterations = {len(scores)}")
print(f"mean       = {scores.mean():.2f}")
print(f"std        = {scores.std():.2f}")
print(f"min        = {scores.min():.2f}")
print(f"max        = {scores.max():.2f}")
print("first 5 samples:", np.round(scores[:5], 2))
iterations = 1000
mean       = 3611.62
std        = 404.07
min        = 2549.86
max        = 5854.48
first 5 samples: [3759.85 4123.13 4309.94 3607.99 3107.44]

The mean (3611.6) sits close to, but not exactly on, the deterministic car assembly score from the contribution analysis tutorial (3540.0, computed from the same point-estimate amounts) — Monte Carlo mean and the plug-in-the-means score only coincide exactly for a linear model with no correlated uncertain inputs, and here they're close but not identical because the model is a product of two independent uncertain factors (steel's CO₂ factor × its 900 kg amount, etc.), and a product of independent random variables has a mean that's not simply the product of means once variance is nonzero.

4. Compare two scenarios

The real payoff of Monte Carlo is comparing options honestly instead of comparing two single numbers. Build a second steel process representing an efficiency retrofit — same uncertainty shape, lower mean CO₂ factor (1.5 instead of 1.8 kg/kg) — and run the same Monte Carlo procedure on a car built from each: 

from scipy import stats as scipy_stats

steel_old = db.new_node(code="steel_old", name="steel production (current process)",
                         unit="kilogram", location="GLO")
steel_old.save()
steel_old.new_exchange(input=steel_old.key, amount=1, type="production").save()
exc_old = steel_old.new_exchange(input=co2.key, amount=1.8, type="biosphere")
exc_old["uncertainty type"] = 3
exc_old["loc"] = 1.8
exc_old["scale"] = 0.2
exc_old.save()

steel_new = db.new_node(code="steel_new", name="steel production (efficiency retrofit)",
                         unit="kilogram", location="GLO")
steel_new.save()
steel_new.new_exchange(input=steel_new.key, amount=1, type="production").save()
exc_new = steel_new.new_exchange(input=co2.key, amount=1.5, type="biosphere")
exc_new["uncertainty type"] = 3
exc_new["loc"] = 1.5
exc_new["scale"] = 0.2
exc_new.save()

def make_car(code, steel_activity):
    car = db.new_node(code=code, name=f"car assembly ({steel_activity['name']})",
                       unit="unit", location="GLO")
    car.save()
    car.new_exchange(input=car.key, amount=1, type="production").save()
    car.new_exchange(input=steel_activity.key, amount=900, type="technosphere").save()
    car.new_exchange(input=electricity.key, amount=2000, type="technosphere").save()
    return car

car_old = make_car("car_old", steel_old)
car_new = make_car("car_new", steel_new)

def run_mc(demand, n=1000, seed=42):
    lca = bc.LCA(demand, method_key, use_distributions=True, seed_override=seed)
    lca.lci()
    lca.lcia()
    scores = [lca.score]
    for _ in range(n - 1):
        next(lca)
        scores.append(lca.score)
    return np.array(scores)

scores_old = run_mc({car_old.key: 1}, seed=42)
scores_new = run_mc({car_new.key: 1}, seed=43)

print("current process : mean=%.1f  std=%.1f" % (scores_old.mean(), scores_old.std()))
print("retrofit process: mean=%.1f  std=%.1f" % (scores_new.mean(), scores_new.std()))
print("mean reduction  : %.1f kg CO2-eq (%.1f%%)" % (
    scores_old.mean() - scores_new.mean(),
    100 * (scores_old.mean() - scores_new.mean()) / scores_old.mean(),
))

t_stat, p_value = scipy_stats.ttest_ind(scores_old, scores_new, equal_var=False)
print("Welch's t-test  : t=%.2f  p=%.2e" % (t_stat, p_value))

p5_old, p95_old = np.percentile(scores_old, [5, 95])
p5_new, p95_new = np.percentile(scores_new, [5, 95])
print("current  90%% interval: [%.1f, %.1f]" % (p5_old, p95_old))
print("retrofit 90%% interval: [%.1f, %.1f]" % (p5_new, p95_new))
overlap = max(0.0, min(p95_old, p95_new) - max(p5_old, p5_new))
print("90%% interval overlap: %.1f kg CO2-eq" % overlap)
frac_new_below_old_mean = (scores_new < scores_old.mean()).mean()
print("fraction of retrofit samples below current mean: %.1f%%" % (100 * frac_new_below_old_mean))
current process : mean=3599.3  std=396.1
retrofit process: mean=3329.0  std=419.6
mean reduction  : 270.4 kg CO2-eq (7.5%)
Welch's t-test  : t=14.81  p=3.81e-47
current  90% interval: [3004.1, 4308.4]
retrofit 90% interval: [2738.2, 4106.3]
90% interval overlap: 1102.3 kg CO2-eq
fraction of retrofit samples below current mean: 76.7%

The two 90% intervals overlap substantially (1102.3 out of roughly 1300–1370 kg CO₂-eq of combined spread) — a naive "do the ranges overlap?" glance would call this inconclusive. The paired statistical test is more informative: Welch's t-test (scipy.stats.ttest_ind, already available since bw2calc depends on scipy — no extra install needed) gives p < 1e-40, and 76.7% of retrofit-process samples land below the current process's mean. Wide overlapping intervals and a clearly significant difference in means are not a contradiction: overlap answers "could a single retrofit-process draw exceed a single current-process draw?" (often yes, given the uncertainty in both), while the t-test/mean-comparison answers "is the retrofit reliably better on average, given 1000 paired samples?" (yes, decisively, here). Which question matters depends on what decision is being made — a one-off shipment vs. a permanent process switch call for different comparisons.

5. use_arrays=True: the non-random sibling

use_distributions=True samples randomly on every next(lca). use_arrays=True is the sibling flag for scenario/array-based iteration: each uncertain (or overridden) value is instead read off a pre-built array, position i on iteration i — useful for stepping through named scenarios (e.g. a set of ecoinvent system-model or price-scenario datapackages) deterministically rather than resampling. Both flags use the same next(lca) mechanism and can be combined; see the bw2calc module map and the bw_processing/matrix_utils module maps for how the underlying array data is laid out. This tutorial only covers the random (use_distributions) case in depth.

Notes & gotchas

  • The field name has a literal space: "uncertainty type", not uncertainty_type. bw2data stores it that way on the exchange dict (bw2data/proxies.py ExchangeDataset.uncertainty); using the underscored name silently sets an unrelated dict key and the exchange stays deterministic with no error.
  • The integer codes are shared, ground-truth-verified constants. They come from stats_arrays.UncertaintyType (uncertainty_types.py): normal = 3, lognormal = 2. The same integers are each distribution class's id attribute (e.g. NormalUncertainty.id == 3) and are what bw_processing stores on disk unchanged — see the stats_arrays module map for the full table of codes.
  • Lognormal's loc is mu (log-space mean), not the median. Verified from distributions/lognormal.py random_variables(), which calls numpy.random.lognormal(params["loc"], params["scale"]) directly — so to center a lognormal on a target median m, set loc = np.log(m), as done for the electricity CH₄ exchange above. Getting this wrong (e.g. passing the median as loc directly) silently shifts the whole distribution rather than raising an error.
  • seed_override makes a run exactly reproducible, not just "similar". Constructing two separate LCA objects with the same seed_override and running the same number of next() calls on each gives bit-identical score sequences (verified: np.allclose(scores, scores2) is True for two independent runs with seed_override=42). Different objects with different seed_override values (as used for the two scenarios above, 42 vs. 43) are independent draws — necessary here so the two scenarios' random noise isn't artificially correlated in a way that would make the comparison look tighter than it is.
  • Monte Carlo mean ≠ the score from plugging in the mean amounts. The 1000-iteration Monte Carlo mean above (3611.6) is close to but not identical to the deterministic score computed from the same point-estimate amounts (3540.0, from the contribution analysis tutorial) — expected for a model that multiplies together more than one independent uncertain quantity, and a reason not to treat a single deterministic run as "the answer" once exchanges carry real uncertainty.
  • Deterministic code paths are unaffected until something samples. Setting "uncertainty type"/loc/scale on an exchange doesn't change what a plain lca.lci(); lca.lcia() (no use_distributions) computes — that still uses the flat amount. Only use_distributions=True (or use_arrays=True) plus a next(lca) call resamples anything.
