Tutorial: Monte Carlo uncertainty analysis

Attach an uncertainty distribution to an exchange, run a stochastic bw2calc.LCA for several iterations, and summarize the resulting score distribution with NumPy.

Everything here uses the real installed bw2calc/bw2data/stats_arrays APIs (.venv/lib/python3.11/site-packages/), verified by running it. See the bw2calc module map and the stats_arrays module map for how these layers fit together, and the Examples page for shorter worked snippets of other workflows.

1. Build a tiny inventory with one uncertain exchange

Exchanges carry uncertainty as plain fields on the exchange dict/proxy — uncertainty_type plus whichever of loc/scale/shape/ minimum/maximum that distribution needs. These field names and the integer uncertainty_type codes come straight from stats_arrays (stats_arrays/uncertainty_types.py UncertaintyType, and each distribution class's id attribute — see the stats_arrays module map); bw2data and bw_processing don't reinterpret them, they just store and pass through the same dtype fields. Here we give a biosphere exchange (a CO₂ emission) a lognormal uncertainty (stats_arrays.LognormalUncertainty, id == 2), where loc is the log-space mean (mu) and scale is the log-space standard deviation (sigma) — see stats_arrays/distributions/lognormal.py LognormalUncertainty.random_variables(), which samples np.random.lognormal(loc, scale, ...)-equivalent draws directly from these two fields: 

import bw2data as bd
import numpy as np
import stats_arrays as sa

bd.projects.set_current("mc_tutorial")

biosphere = bd.Database("biosphere")
biosphere.register()
co2 = biosphere.new_node(code="co2", name="carbon dioxide", unit="kilogram", type="emission")
co2.save()

db = bd.Database("example_db")
db.register()

steel = db.new_node(code="steel", name="steel production", unit="kilogram", location="GLO", type="process")
steel.save()
steel.new_edge(input=steel.key, amount=1, type="production").save()

# Without uncertainty fields, an exchange has no uncertainty_type at all:
exc = steel.new_edge(input=co2.key, amount=2.5, type="biosphere")
exc.save()
print(exc.get("uncertainty_type", "not set"))
not set

Now save it again with a real distribution attached: 

exc["uncertainty_type"] = sa.LognormalUncertainty.id  # 2
exc["loc"] = np.log(2.5)   # mu, in log-space (median amount stays 2.5)
exc["scale"] = 0.2         # sigma
exc.save()

print(sa.LognormalUncertainty.id, sa.LognormalUncertainty.description)
2 Lognormal uncertainty

amount is the point estimate used by an ordinary (non-stochastic) LCA; uncertainty_type/loc/scale/... only take effect when the LCA is told to sample distributions (next step). Any other distribution in stats_arrays works the same way — e.g. sa.TriangularUncertainty.id (5) needs minimum/loc(mode)/maximum instead of loc/scale.

2. Register an LCIA method that scores the uncertain flow

bd.Method(name).write([(flow_key_or_id, cf), ...]) (bw2data/method.py) creates/overwrites a characterization method — here a one-flow "gwp" method that just passes CO₂ through with a factor of 1: 

method = ("example", "gwp")
bd.Method(method).write([(co2.key, 1)])

3. Create a stochastic LCA object

Pass use_distributions=True to bc.LCA(...) (bw2calc/lca.py LCA.__init__) so that, instead of using each exchange's fixed amount, the technosphere/biosphere/characterization matrices are rebuilt from matrix_utils.MappedMatrix objects that resample from stats_arrays distributions on every iteration. Also pass a fixed seed_override (an int, threaded down to every underlying MappedMatrix — see bw2calc/lca_base.py LCABase.load_lci_data() line ~46) so the whole run is reproducible instead of drawing a fresh OS-entropy seed each time: 

import bw2calc as bc

lca = bc.LCA({steel: 1}, method=method, use_distributions=True, seed_override=42)
lca.lci()
lca.lcia()
print("first score", lca.score)
first score 2.7611122622639517

This first lca.score already used one random draw of the CO₂ amount (not exactly 2.5, because lci()/lcia() build the matrices from the datapackage's distributions the moment use_distributions=True is set — there is no separate "static first pass").

4. Iterate: resample and recompute

An LCA object is itself a Python Iterator (bw2calc/lca_base.py class LCABase(Iterator)). Each next(lca) — or one step of a for/zip loop over lca — calls next() on every underlying MappedMatrix (technosphere, biosphere, characterization), which draws a fresh set of random values for every uncertain field and rebuilds the matrices (bw2calc/lca.py LCA.__next__). It does not resolve the linear system itself — call lca.lci_calculation() and lca.lcia_calculation() (or just lca.lcia()) afterwards to get the new lca.score: 

scores = [lca.score]                 # keep the first draw from step 3
for _ in zip(lca, range(49)):        # 49 more draws -> 50 total
    lca.lcia_calculation()
    scores.append(lca.score)

print(len(scores), scores[:5])
50 [2.7611122622639517, 2.4318150176608437, 2.845755168932493, 3.3902265086151977, 2.385622470953585]

zip(lca, range(49)) is just a concise way to step the iterator exactly 49 times; for _ in lca: ... alone would iterate forever since LCA never raises StopIteration on its own.

5. Summarize the score distribution

The collected scores are a plain list of floats — hand them to numpy for summary statistics: 

import numpy as np

scores = np.array(scores)
print("iterations:", len(scores))
print("mean :", round(scores.mean(), 4))
print("std  :", round(scores.std(), 4))
print("min  :", round(scores.min(), 4))
print("max  :", round(scores.max(), 4))
iterations: 50
mean : 2.4312
std  : 0.4569
min  : 1.6894
max  : 3.621

Full example, start to finish

import bw2data as bd
import bw2calc as bc
import numpy as np
import stats_arrays as sa

bd.projects.set_current("mc_tutorial")

biosphere = bd.Database("biosphere")
biosphere.register()
co2 = biosphere.new_node(code="co2", name="carbon dioxide", unit="kilogram", type="emission")
co2.save()

db = bd.Database("example_db")
db.register()

steel = db.new_node(code="steel", name="steel production", unit="kilogram", location="GLO", type="process")
steel.save()
steel.new_edge(input=steel.key, amount=1, type="production").save()

steel.new_edge(
    input=co2.key,
    amount=2.5,
    type="biosphere",
    uncertainty_type=sa.LognormalUncertainty.id,  # 2
    loc=np.log(2.5),   # mu, in log-space
    scale=0.2,         # sigma
).save()

method = ("example", "gwp")
bd.Method(method).write([(co2.key, 1)])

lca = bc.LCA({steel: 1}, method=method, use_distributions=True, seed_override=42)
lca.lci()
lca.lcia()

scores = [lca.score]
for _ in zip(lca, range(49)):     # 49 more iterations -> 50 total
    lca.lcia_calculation()
    scores.append(lca.score)

scores = np.array(scores)
print("iterations:", len(scores))
print("mean :", round(scores.mean(), 4))
print("std  :", round(scores.std(), 4))
print("min  :", round(scores.min(), 4))
print("max  :", round(scores.max(), 4))
iterations: 50
mean : 2.4312
std  : 0.4569
min  : 1.6894
max  : 3.621

Notes & gotchas

  • Without seed_override, results are genuinely random. Omitting it lets each MappedMatrix draw its own seed from OS entropy (bw2calc/utils.py get_seed()), so exact scores differ between runs — only the shape of the distribution (mean/std in the right ballpark for the parameters chosen) is guaranteed to reproduce. With seed_override=42 as used above, the exact numbers printed here reproduce run to run (verified by running the full example twice back to back).
  • use_distributions=True is what turns on sampling. Without it, an LCA just uses each exchange's fixed amount and ignores uncertainty_type/loc/scale/... entirely — an activity or exchange can carry uncertainty data indefinitely without it ever affecting an ordinary lca.lci()/lca.lcia() call.
  • Iterating rebuilds all matrices with use_distributions=True, not just the one uncertain cell. Every resource across the technosphere/biosphere/characterization datapackages that was built with use_distributions=True is resampled each next(lca) (bw2calc/lca.py LCA.__next__ loops over self.matrix_labels); this example only has one stochastic value, but a larger inventory would resample every uncertain exchange together on each iteration.
  • The first score is already stochastic. Building the LCA object with use_distributions=True and calling lci()/lcia() once already draws a random sample — there's no separate "static baseline" pass to skip before Monte Carlo begins, so include that first lca.score in your collected samples (as done in step 4) rather than discarding it.
  • Selective control per matrix. The selective_use argument to bc.LCA(...) (see bw2calc/lca.py LCA.__init__) can turn use_distributions on/off per matrix label (e.g. sample the biosphere matrix but keep the technosphere matrix fixed) instead of the same flag applying to all three.
  • An always-forward iterator. LCA never raises StopIteration — a bare for _ in lca: loop runs forever; bound it explicitly, e.g. with zip(lca, range(n)) or a plain counted for/while loop as shown above.
  • For very large Monte Carlo batches, where only the final scores (not full inventory/characterized matrices) are needed per iteration, bw2calc.FastScoresOnlyMultiLCA (bw2calc/fast_scores.py) skips retaining the intermediate matrices for a leaner loop — worth reaching for once iteration counts get into the thousands. This tutorial's plain LCA iteration loop is the simplest correct starting point.
