Tutorial: find an LCA result's biggest contributors

How to take an already-solved bw2calc.LCA result and use bw2analyzer.ContributionAnalysis to find which processes and which biosphere flows actually drive the score.

Everything here uses the real installed bw2analyzer API (.venv/lib/python3.11/site-packages/bw2analyzer/), verified by running it. See the bw2analyzer module map for the full picture of what else it can do, and the bw2calc module map for how LCA itself works.

1. Build a tiny multi-process system

A single-process inventory (like the bw2data example this tutorial continues from) has nothing to rank — contribution analysis is only interesting once several activities and flows can compete for "biggest". Here a car assembly process draws on two component processes, each with its own emissions: 

import bw2data as bd

bd.projects.set_current("tutorial-project")

biosphere = bd.Database("biosphere")
biosphere.register()
co2 = biosphere.new_node(code="co2", name="carbon dioxide", unit="kilogram", type="emission")
co2.save()
ch4 = biosphere.new_node(code="ch4", name="methane", unit="kilogram", type="emission")
ch4.save()

db = bd.Database("example_db")
db.register()

steel = db.new_node(code="steel", name="steel production", unit="kilogram", location="GLO")
steel.save()
steel.new_exchange(input=steel.key, amount=1, type="production").save()
steel.new_exchange(input=co2.key, amount=1.8, type="biosphere").save()

electricity = db.new_node(code="electricity", name="electricity production", unit="kilowatt hour", location="GLO")
electricity.save()
electricity.new_exchange(input=electricity.key, amount=1, type="production").save()
electricity.new_exchange(input=co2.key, amount=0.4, type="biosphere").save()
electricity.new_exchange(input=ch4.key, amount=0.02, type="biosphere").save()

car = db.new_node(code="car", name="car assembly", unit="unit", location="GLO")
car.save()
car.new_exchange(input=car.key, amount=1, type="production").save()
car.new_exchange(input=steel.key, amount=900, type="technosphere").save()
car.new_exchange(input=electricity.key, amount=2000, type="technosphere").save()

car assembly has no biosphere exchanges of its own — every gram of CO₂/CH₄ in this system comes from the two components it draws on, in different amounts. That asymmetry is what the rest of this tutorial ranks.

2. Characterize and solve the LCA

Register a Method giving methane a much higher characterization factor than CO₂ (a simplified GWP100), then solve for one car: 

import bw2calc as bc

method_key = ("tutorial_method", "gwp")
method = bd.Method(method_key)
method.register(unit="kg CO2-eq")
method.write([(co2.key, 1.0), (ch4.key, 28.0)])   # CH4 = 28x CO2-eq (GWP100)

lca = bc.LCA({car.key: 1}, method_key)
lca.lci()
lca.lcia()
print(lca.score)
3539.999943971635

lca.score is a single number — useful for comparing scenarios, useless for explaining why the number is what it is. That's what bw2analyzer is for.

3. Rank the processes

ContributionAnalysis.annotated_top_processes(lca) (contribution.py line ~127) sums lca.characterized_inventory per technosphere activity and returns (score, supply_amount, activity) tuples, sorted by abs(score) descending: 

import bw2analyzer as ba

ca = ba.ContributionAnalysis()
for score, amount, act in ca.annotated_top_processes(lca):
    print(f"{score:8.1f} kg CO2-eq   {amount:8.1f} {act['unit']:12s} {act}")
  1920.0 kg CO2-eq     2000.0 kilowatt hour 'electricity production' (kilowatt hour, GLO, None)
  1620.0 kg CO2-eq      900.0 kilogram     'steel production' (kilogram, GLO, None)
     0.0 kg CO2-eq        1.0 unit         'car assembly' (unit, GLO, None)

electricity production edges out steel production here even though car assembly uses more mass of steel — because per-unit, electricity carries the (28×-weighted) methane emission steel doesn't. car assembly itself scores 0.0: it has no biosphere exchanges of its own, so it contributes nothing directly — see the gotcha about this below.

4. Rank the biosphere flows

annotated_top_emissions(lca) (contribution.py line ~147) does the same sort, but summing per biosphere flow instead of per activity — (score, inventory_amount, flow) tuples: 

for score, amount, flow in ca.annotated_top_emissions(lca):
    print(f"{score:8.1f} kg CO2-eq   {amount:8.3f} {flow['unit']:8s} {flow}")
  2420.0 kg CO2-eq   2420.000 kilogram 'carbon dioxide' (kilogram, GLO, None)
  1120.0 kg CO2-eq     40.000 kilogram 'methane' (kilogram, GLO, None)

By raw mass, CO₂ outweighs CH₄ by 60× (2420 kg vs. 40 kg) — but by characterized score it's only about 2×, because the GWP100 factor written in step 2 weights every kilogram of methane 28× more heavily. This is the actual point of contribution analysis: it ranks by impact, not by inventory quantity, which is often not the same ordering.

Full example, start to finish

import bw2data as bd
import bw2calc as bc
import bw2analyzer as ba

bd.projects.set_current("tutorial-project")

biosphere = bd.Database("biosphere")
biosphere.register()
co2 = biosphere.new_node(code="co2", name="carbon dioxide", unit="kilogram", type="emission")
co2.save()
ch4 = biosphere.new_node(code="ch4", name="methane", unit="kilogram", type="emission")
ch4.save()

db = bd.Database("example_db")
db.register()

steel = db.new_node(code="steel", name="steel production", unit="kilogram", location="GLO")
steel.save()
steel.new_exchange(input=steel.key, amount=1, type="production").save()
steel.new_exchange(input=co2.key, amount=1.8, type="biosphere").save()

electricity = db.new_node(code="electricity", name="electricity production", unit="kilowatt hour", location="GLO")
electricity.save()
electricity.new_exchange(input=electricity.key, amount=1, type="production").save()
electricity.new_exchange(input=co2.key, amount=0.4, type="biosphere").save()
electricity.new_exchange(input=ch4.key, amount=0.02, type="biosphere").save()

car = db.new_node(code="car", name="car assembly", unit="unit", location="GLO")
car.save()
car.new_exchange(input=car.key, amount=1, type="production").save()
car.new_exchange(input=steel.key, amount=900, type="technosphere").save()
car.new_exchange(input=electricity.key, amount=2000, type="technosphere").save()

method_key = ("tutorial_method", "gwp")
method = bd.Method(method_key)
method.register(unit="kg CO2-eq")
method.write([(co2.key, 1.0), (ch4.key, 28.0)])

lca = bc.LCA({car.key: 1}, method_key)
lca.lci()
lca.lcia()
print(lca.score)

ca = ba.ContributionAnalysis()
for score, amount, act in ca.annotated_top_processes(lca):
    print(round(score, 1), act["name"])
for score, amount, flow in ca.annotated_top_emissions(lca):
    print(round(score, 1), flow["name"])
3539.999943971635
1920.0 electricity production
1620.0 steel production
0.0 car assembly
2420.0 carbon dioxide
1120.0 methane

Notes & gotchas

  • This ranks direct contributions, not subtree totals. Each activity's score is its own row/column sum of lca.characterized_inventory — already scaled by how much of that activity the solved technosphere system needed, but not rolled up with the activities it consumes. That's why car assembly scores 0.0 above even though it's the functional unit: it has no biosphere exchanges of its own, and its component activities' scores aren't added into it. For a genuinely recursive, percentage-of-parent breakdown down the supply chain, use bw2analyzer.utils.print_recursive_calculation instead (utils.py, needs a method) or tagged.py traverse_tagged_databases if you want to aggregate by a custom tag rather than by individual activity.
  • Sorted by abs(value), default limit 25. Both methods funnel through sort_array (contribution.py line ~6), which sorts by absolute value (so a large negative — e.g. an avoided-burden credit — ranks as "top" too) and returns at most 25 rows by default. Pass limit=10 for fewer, or limit_type="percent", limit=0.05 to return everything at or above 5% of the total instead of a fixed count.
  • names=True (the default) costs one database lookup per result. annotated_top_processes/annotated_top_emissions call bw2data.get_activity() for every row to attach the full activity/flow object. Pass names=False to get raw (database, code) keys instead if you're ranking hundreds of rows and don't need the metadata immediately.
  • Lower-level building blocks, if you need them. top_processes(matrix, **kwargs) and top_emissions(matrix, **kwargs) do the same ranking without the activity lookup — useful if you're working directly with a characterized-inventory-shaped matrix that didn't come from a live LCA object. sort_array itself is the generic "rank this 1-d array" primitive underneath both.
