Tutorial: import external inventory data

Step by step through bw2io's extract → apply strategies → check for unlinked exchanges → match/link → write pipeline, using ExcelImporter and the bundled example.xlsx fixture to bring an external spreadsheet into a real bw2data database.

Everything here uses the real installed bw2io/bw2data API (.venv/lib/python3.11/site-packages/bw2io/, .venv/lib/python3.11/site-packages/bw2data/), verified by running it. See the bw2io module map for the full importer/strategy landscape and the bw2data module map for what a "database" and "activity" are underneath. See also the site-wide Examples page for more verified, runnable snippets across every module.

1. Set up a project and a stand-in biosphere database

Brightway isolates data into projects (see the empty-database tutorial for the basics), so pick one first: 

import bw2data as bd
import bw2io as bi

bd.projects.set_current("import_tutorial")

The example workbook has exchanges pointing at a biosphere3 database (elementary flows like "Ammonia" and "Carbon dioxide, fossil"). In a normal project this already exists, built once by bw2io.bw2setup() / create_default_biosphere3() (see the bw2io module map). This tutorial doesn't want to depend on downloading that, so we hand-build a tiny stand-in with just the five flows this exact file needs — inspected up front with openpyxl to see which ones those are: 

biosphere = bd.Database("biosphere3")
biosphere.register()
flows = [
    {"name": "Ammonia", "categories": ("air", "urban air close to ground"), "unit": "kilogram"},
    {"name": "Methanol", "categories": ("air",), "unit": "kilogram"},
    {"name": "BOD5, Biological Oxygen Demand", "categories": ("water", "surface water"), "unit": "kilogram"},
    {"name": "Carbon dioxide, fossil", "categories": ("air",), "unit": "kilogram"},
    {"name": "Suspended solids, unspecified", "categories": ("water",), "unit": "kilogram"},
]
for flow in flows:
    node = biosphere.new_node(code=flow["name"], location=None, type="emission", **flow)
    node.save()

print(len(biosphere))  # 5

Note the explicit location=None. SQLiteBackend.new_node() (bw2data/backends/base.py ~line 867: if "location" not in kwargs: obj["location"] = config.global_location) silently defaults a node's location to "GLO" if you don't pass one — but the biosphere exchanges in the workbook have no location field at all once the importer's strip_biosphere_exc_locations strategy runs. Since the matching logic hashes on location too (see step 4), a node stamped "GLO" would never match an exchange with no location and would stay silently unlinked.

This matters before we even build the importer: ExcelImporter's built-in strategy list already tries to link biosphere exchanges against bw2data.config.biosphere (defaults to "biosphere3") as one of its standard steps — see step 3. That strategy only succeeds if the database it points at already has matching data in it, so the biosphere has to exist first.

2. Locate the workbook and construct the importer

bw2io ships this fixture at data/examples/example.xlsx; get_xlsx_example_filepath() (bw2io/__init__.py) returns its path. ExcelImporter.__init__ (bw2io/importers/excel.py lines 99–139) does the extract stage immediately — before you call anything else — by handing the filepath to ExcelExtractor.extract(), dropping any worksheet whose first cell is literally "skip" (valid_first_cell, line 31; the fixture has one such sheet used purely as an in-file comment), locating the single "Database" metadata block (get_database, line 141), and walking every "Activity" section into a plain dict with an "exchanges" list (process_activities/get_activity, lines 254–383). Nothing touches bw2data yet — imp.data is just Python dicts: 

fp = bi.get_xlsx_example_filepath()
print(fp.name)  # example.xlsx

imp = bi.ExcelImporter(fp)
print(imp.db_name)                        # BW2 Excel example
print(len(imp.data))                      # 3
print(sorted(ds["name"] for ds in imp.data))
# ['Acetic acid, at plant', 'Electricity, at Grid, US, 2008', 'Methanol, at plant']

3. Apply the strategy pipeline

imp.strategies is the ordered list ExcelImporter.__init__ builds (excel.py lines 100–120): CSV/Excel-cell cleanup (csv_restore_tuples, csv_numerize, ...), unit normalization, set_code_by_activity_hash, a biosphere-linking step, assign_only_product_as_production, link_technosphere_by_activity_hash, and uncertainty cleanup. ImportBase.apply_strategies (bw2io/importers/base.py lines 98–135) runs each one in order via apply_strategy (lines 51–96), which calls self.data = strategy(self.data), appends the function's name to self.applied_strategies, and — notably — catches StrategyError and just prints it rather than raising, so one misbehaving strategy doesn't abort the whole pipeline: 

imp.apply_strategies(verbose=False)
print(imp.applied_strategies)
# ['csv_restore_tuples', 'csv_restore_booleans', 'csv_numerize', 'csv_drop_unknown',
#  'csv_restore_temporal_distributions', 'csv_add_missing_exchanges_section', 'normalize_units',
#  'strip_biosphere_exc_locations', 'set_code_by_activity_hash', 'link_iterable_by_fields',
#  'assign_only_product_as_production', 'link_technosphere_by_activity_hash',
#  'drop_falsey_uncertainty_fields_but_keep_zeros', 'convert_uncertainty_types_to_integers',
#  'convert_activity_parameters_to_list']

nodes, edges, unlinked, multifunctional = imp.statistics(print_stats=False)
print(nodes, edges, unlinked, multifunctional)  # 3 9 3 0

The link_iterable_by_fields entry in that list is functools.partial(link_iterable_by_fields, other=Database(config.biosphere), edge_kinds=["biosphere"]) (excel.py lines 110–114) — it's what just linked all 5 biosphere exchanges against the biosphere3 stand-in from step 1, with no extra call needed on our part.

4. Check what's still unlinked

LCIImporter.statistics() (bw2io/importers/base_lci.py lines 91–154) is the summary view (it's what printed the 3 9 3 0 above); ImportBase.unlinked (bw2io/importers/base.py lines 137–159) iterates the actual unique unlinked exchange dicts, deduplicated by activity_hash: 

print(sorted((exc["type"], exc["name"]) for exc in imp.unlinked))
# [('production', 'Acetic acid, at plant'), ('technosphere', 'Methanol, at plant')]

That's surprising: both "Acetic acid, at plant" and "Methanol, at plant" are in imp.data — this is a self-contained file, everything should link internally. The cause is activity_hash's default field list, ("name", "categories", "unit", "reference product", "location") (bw2io/utils.py line 44): assign_only_product_as_production (strategies/generic.py lines 264–278), which ran earlier in the pipeline, writes a "reference product" key onto each node dict, but the corresponding production/technosphere exchange dict pointing at it never gets that key — so their hashes disagree and link_technosphere_by_activity_hash silently fails to connect them, with no warning: 

from bw2io.utils import activity_hash

acetic = next(ds for ds in imp.data if ds["name"] == "Acetic acid, at plant")
print(repr(acetic.get("reference product")))  # 'Acetic acid, at plant'

prod_exc = next(e for e in acetic["exchanges"] if e["type"] == "production")
print("reference product" in prod_exc)  # False

print(activity_hash(acetic) == activity_hash(prod_exc))  # False -- the mismatch

5. Link the remaining exchanges explicitly

LCIImporter.match_database(db_name=None, fields=..., ...) (base_lci.py lines 391–449) wraps the same link_iterable_by_fields call, internally (db_name=None) or against another written database (db_name="some_other_db"). Passing an explicit fields list that leaves out "reference product" sidesteps the gotcha from step 4: 

imp.match_database(fields=["name", "unit", "location", "categories"])

nodes, edges, unlinked, multifunctional = imp.statistics(print_stats=False)
print(nodes, edges, unlinked, multifunctional)  # 3 9 0 0
print(imp.all_linked)                            # True

6. Write to bw2data

LCIImporter.write_database(...) (base_lci.py lines 286–373) validates every dataset belongs to the same database name (raising WrongDatabase otherwise) and that codes are unique (NonuniqueCode), registers the database if it doesn't exist yet, then calls bw2data.Database(db_name).write(existing, ...) — the same low-level write the empty-database tutorial shows via db.write(data) directly. ExcelImporter overrides write_database only to default activate_parameters=True (excel.py lines 298–301): 

def write_database(self, **kwargs):
    kwargs["activate_parameters"] = kwargs.get("activate_parameters", True)
    super(ExcelImporter, self).write_database(**kwargs)

That override calls super().write_database(**kwargs) without a return — so imp.write_database() on an ExcelImporter gives you None, even though the base LCIImporter.write_database it calls does return the new Database instance. Fetch the written database separately: 

imp.write_database()

db = bd.Database("BW2 Excel example")
print(len(db))  # 3
for act in sorted(db, key=lambda a: a["name"]):
    print(act["name"], sorted(
        (e["type"], e.input["name"], round(e["amount"], 6)) for e in act.exchanges()
    ))
# Acetic acid, at plant [('biosphere', 'Ammonia', 0.00057), ('biosphere', 'Methanol', 4e-05),
#                         ('production', 'Acetic acid, at plant', 1), ('technosphere', 'Methanol, at plant', 0.539)]
# Electricity, at Grid, US, 2008 []
# Methanol, at plant [('biosphere', 'BOD5, Biological Oxygen Demand', 5.8e-05),
#                      ('biosphere', 'Carbon dioxide, fossil', 0.53),
#                      ('biosphere', 'Suspended solids, unspecified', 8.8e-05),
#                      ('production', 'Methanol, at plant', 1),
#                      ('technosphere', 'Electricity, at Grid, US, 2008', 0.00805)]

Every exchange resolved to a real activity — db.write() also rebuilds the bw_processing datapackage automatically, so this database is immediately usable by bw2calc.LCA just like any other.

Full example, start to finish

import bw2data as bd
import bw2io as bi

bd.projects.set_current("import_tutorial")

# 1. Minimal biosphere3 stand-in matching only the flows example.xlsx needs.
biosphere = bd.Database("biosphere3")
biosphere.register()
flows = [
    {"name": "Ammonia", "categories": ("air", "urban air close to ground"), "unit": "kilogram"},
    {"name": "Methanol", "categories": ("air",), "unit": "kilogram"},
    {"name": "BOD5, Biological Oxygen Demand", "categories": ("water", "surface water"), "unit": "kilogram"},
    {"name": "Carbon dioxide, fossil", "categories": ("air",), "unit": "kilogram"},
    {"name": "Suspended solids, unspecified", "categories": ("water",), "unit": "kilogram"},
]
for flow in flows:
    node = biosphere.new_node(code=flow["name"], location=None, type="emission", **flow)
    node.save()

# 2. Extract (happens inside the constructor).
fp = bi.get_xlsx_example_filepath()
imp = bi.ExcelImporter(fp)

# 3. Apply strategies (also auto-links biosphere against the database above).
imp.apply_strategies(verbose=False)

# 4. Check for unlinked exchanges.
nodes, edges, unlinked, multifunctional = imp.statistics(print_stats=False)
print("after strategies:", nodes, edges, unlinked, multifunctional)

# 5. Match/link the rest internally (excluding "reference product" -- see step 4 above).
imp.match_database(fields=["name", "unit", "location", "categories"])
nodes, edges, unlinked, multifunctional = imp.statistics(print_stats=False)
print("after matching:  ", nodes, edges, unlinked, multifunctional)
print("all_linked:", unlinked == 0)  # imp.all_linked would print the same statistics again

# 6. Write.
imp.write_database()
db = bd.Database("BW2 Excel example")
print(len(db), "activities written")
after strategies: 3 9 3 0
Applying strategy: link_iterable_by_fields
after matching:   3 9 0 0
all_linked: True
Created database: BW2 Excel example
3 activities written

Notes & gotchas

  • Silent non-linking, not errors. Every mismatch in this tutorial (the location default, the "reference product" hash gotcha) leaves exchanges unlinked with no exception and no warning — the only way to catch it is to actually call .statistics() or check .all_linked before .write_database(). Nothing stops you from writing a database full of unlinked exchanges.
  • new_node() defaults location to config.global_location ("GLO") if you don't pass one (bw2data/backends/base.py ~line 867) — pass location=None explicitly when hand-building nodes meant to match exchanges that have no location field, as biosphere exchanges do once strip_biosphere_exc_locations has run.
  • activity_hash's default fields include "reference product". assign_only_product_as_production sets that field on process nodes but not on the exchanges pointing at them, so internal technosphere/production linking via the importer's default strategy list (fields=None) will under-link on data shaped like this workbook. Passing an explicit fields list to match_database (or to link_technosphere_by_activity_hash / link_iterable_by_fields directly) that excludes it fixes this.
  • ExcelImporter.write_database() returns None, not the Database instance the base LCIImporter.write_database() it wraps returns (excel.py lines 298–301 call super()... without a return). Look the database up with bd.Database(db_name) afterward instead of relying on the return value.
  • The "skip" and "cutoff" conventions are real, not documentation fluff. The bundled example.xlsx actually has a worksheet whose A1 cell is "skip" (silently dropped, valid_first_cell in excel.py line 31), and its first data sheet uses cutoff in A1 to tell the extractor to ignore columns past a given index (process_activities/cut_worksheet, excel.py lines 264–272) — handy for keeping notes/formulas in the spreadsheet itself without the importer choking on them.
  • This is one importer among many. Every format-specific importer (SimaProCSVImporter, SingleOutputEcospold2Importer, ...) is a subclass of the same ImportBase / LCIImporter shown here, with a different extractor and a different self.strategies list tailored to that format's quirks — see the bw2io module map's "Where to look" section for the SimaPro and ecoinvent equivalents of this walkthrough.
