bw2parameters

The formula-evaluation engine for Brightway: a safe expression interpreter (built on asteval) plus a dependency-ordered ParameterSet for evaluating interdependent named parameters, with optional pint unit awareness. Consumed by bw2data.parameters to evaluate parameterized exchanges and activities — it has no knowledge of Brightway's data model itself, only plain dicts and formula strings.

Installed at .venv/lib/python3.11/site-packages/bw2parameters/, version 1.1.0 (PyPI bw2parameters). Built on asteval (safe expression parsing), astunparse (AST → source), pint (units), and stats_arrays (Monte Carlo uncertainty sampling).

Typical usage

Evaluating a formula directly with Interpreter

from bw2parameters import Interpreter

interp = Interpreter()
result = interp.eval("2 * mass + offset", known_symbols={"mass": 4, "offset": 1})
# result == 9

Evaluating interdependent named parameters with ParameterSet

from bw2parameters import ParameterSet

params = {
    "mass":   {"amount": 10},
    "density": {"amount": 2.5},
    "volume": {"formula": "mass / density"},
}

ps = ParameterSet(params)
result = ps.evaluate()
# result == {"volume": 4.0, "mass": 10, "density": 2.5}
# ps.order gives the evaluation order, e.g. ["mass", "density", "volume"]

# Or evaluate and write results back into the `amount` field in place:
ps.evaluate_and_set_amount_field()

Namespacing parameters from two scopes before combining them

from bw2parameters import prefix_parameter_dict

activity_params = {"efficiency": {"formula": "base_rate * 1.1"}}
namespaced, substitutions = prefix_parameter_dict(activity_params, "act1__")
# namespaced == {"act1__efficiency": {"formula": "(base_rate * 1.1)", "original": "efficiency"}}

Where to look

How does a formula string actually get evaluated?

interpreter.py, Interpreter.eval() — injects known_symbols into the symbol table, calls the underlying asteval.Interpreter.eval, then removes them again; wraps NameError/SyntaxError into errors.MissingName.

How are dependent parameters evaluated in the correct order?

parameter_set.py, ParameterSet.get_references() (builds a name → dependency-set map using Interpreter.get_unknown_symbols) and ParameterSet.get_order() (topological sort; raises ParameterError on unresolved/circular references, or CapitalizationError if the mismatch looks like a case typo).

How do units get parsed and attached to values?

pint.py, PintWrapperSingleton — wraps a shared pint.UnitRegistry. Consumed by interpreter.PintInterpreter and parameter_set.PintParameterSet, which additionally track a parameter's unit field alongside amount.

How does Monte Carlo / stochastic evaluation work?

parameter_set.py, ParameterSet.evaluate_monte_carlo(iterations=1000) — samples each parameter's uncertainty distribution via stats_arrays.uncertainty_choices; every formula must return a 1-D array of shape (iterations,) or errors.BroadcastingError is raised.

How are parameters from different scopes (project/database/activity) combined without name collisions?

mangling.py — prefix_parameter_dict(dct, prefix) renames dict keys and rewrites formula references via mangle_formula; substitute_in_formulas/FormulaSubstitutor apply an explicit {old: new} rename map. This is what bw2data.parameters.ParameterManager uses to merge scoped parameter sets.

What exceptions can this package raise?

errors.py — all inherit ValidationError: MissingName (undefined variable in a formula), SelfReference (parameter references itself), DuplicateName (name collides with a built-in), CapitalizationError (likely case-mismatch), BroadcastingError (bad Monte Carlo array shape), ParameterError (generic ordering/definition failure).

Related modules

bw2data — the main consumer: bw2data/parameters.py defines ProjectParameter/DatabaseParameter/ActivityParameter/ParameterManager, which build the plain-dict parameter sets that bw2parameters.ParameterSet evaluates.
bw2calc — downstream: LCA calculations run on exchange amounts that bw2data may have already resolved from formulas via this package.
stats_arrays — supplies the uncertainty distributions sampled by ParameterSet.evaluate_monte_carlo.
