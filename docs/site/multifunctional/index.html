multifunctional

A bw2data database-backend plugin that resolves multi-output ("multifunctional") processes by allocation or substitution, so ordinary square-matrix LCA calculations can be run on them.

Installed at .venv/lib/python3.11/site-packages/multifunctional/, version 1.1.1. Upstream repo: brightway-lca/multifunctional. Registers itself into bw2data automatically — bw2data/__init__.py does import multifunctional.

The plugin mechanism

multifunctional doesn't monkeypatch bw2data — it registers itself into two mapping dicts that bw2data consults by backend string: 

from bw2data.subclass_mapping import DATABASE_BACKEND_MAPPING, NODE_PROCESS_CLASS_MAPPING

DATABASE_BACKEND_MAPPING["multifunctional"] = MultifunctionalDatabase
NODE_PROCESS_CLASS_MAPPING["multifunctional"] = multifunctional_node_dispatcher

Because bw2data/__init__.py itself tries import multifunctional at import time, simply having this package installed is enough: any database created with bd.Database(name, backend="multifunctional") gets routed to MultifunctionalDatabase, and each row loaded from it is wrapped by whichever class multifunctional_node_dispatcher() decides — ReadOnlyProcessWithReferenceProduct for allocation-generated nodes, MaybeMultifunctionalProcess for everything else.

Typical usage

import bw2data as bd

bd.projects.set_current("mf-example")

db = bd.Database("mf-db", backend="multifunctional")
db.register()

db.write({
    ("mf-db", "chp"): {
        "name": "combined heat and power",
        "type": "multifunctional",
        "default_allocation": "price",
        "exchanges": [
            {"amount": 1, "type": "production", "functional": True,
             "name": "electricity", "unit": "kWh",
             "properties": {"price": 0.30}},
            {"amount": 4, "type": "production", "functional": True,
             "name": "heat", "unit": "MJ",
             "properties": {"price": 0.02}},
            {"input": ("biosphere", "co2"), "amount": 0.5, "type": "biosphere"},
        ],
    },
})

# .process() (called on write/save, or explicitly) runs allocation for every
# multifunctional node, generating read-only single-output processes for
# "electricity" and "heat", each carrying a price-based share of the inputs.
db.process()

# bw2calc can then run an LCA against either allocated product directly
electricity = bd.get_node(database="mf-db", name="electricity")

For a slower-paced, explanatory walkthrough of the same territory — one worked refinery example built up step by step, with a from-first-principles check that the allocated scores sum back to the parent's total — see the step-by-step tutorial.

Gotcha found while writing those examples: don't put an explicit "input" on a functional exchange unless it already points at an existing product node — a same-key placeholder gets stripped by generic_allocation() (allocation.py) before it generates a fresh code, but a made-up "input" pointing nowhere makes the datapackage build raise UnknownObject. Also, MultifunctionalDatabase.process() (called automatically by write()) runs allocation unconditionally, so default_allocation must already be set (on the database via db.register(default_allocation=...), or per-node) before the first write(), or it raises ValueError.

Where to look

How does a "multifunctional" backend database actually activate this package?

__init__.py — registers MultifunctionalDatabase into bw2data.subclass_mapping.DATABASE_BACKEND_MAPPING["multifunctional"] and multifunctional_node_dispatcher into NODE_PROCESS_CLASS_MAPPING["multifunctional"]. See "The plugin mechanism" above.

Where does allocation actually run, and when?

database.py MultifunctionalDatabase.process() calls node.allocate() on every multifunctional node before building the datapackage; the per-node logic is node_classes.py MaybeMultifunctionalProcess.allocate(), which dispatches to allocation.py generic_allocation().

How do I add a custom allocation strategy, e.g. by a "volume" property?

custom_allocation.py add_custom_property_allocation_to_project("volume") — registers it in allocation_strategies and persists it to the current project (restored on project switch via update_allocation_strategies_on_project_change). Validate first with check_property_for_allocation() / list_available_properties().

What is a "read-only" process, and why can't I edit it directly?

node_classes.py ReadOnlyProcessWithReferenceProduct — generated per functional product by allocation; its __setitem__/copy/new_edge raise NotImplementedError, and its exchanges use edge_classes.py ReadOnlyExchange/ReadOnlyExchanges which block mutation too. Edit the parent process (.parent property, via mf_parent_key) and re-run allocation instead.

How are stale allocation results cleaned up when I edit a process?

utils.py purge_expired_linked_readonly_processes(), called from MaybeMultifunctionalProcess.save(). Each allocation run stamps a fresh mf_allocation_run_uuid on the parent (in allocation.py generic_allocation()); read-only children with a stale UUID are deleted.

What built-in allocation strategies exist and what data do they need?

allocation.py allocation_strategies: "price" and "mass" (numeric property on the functional edge or its linked product, normalized by production amount), "equal" (factor 1.0 per functional edge), "manual_allocation" (uses a manual_allocation property directly, not normalized).

Related modules

bw2data — the core data model this package plugs into; provides SQLiteBackend, Activity/Exchange, and the DATABASE_BACKEND_MAPPING / NODE_PROCESS_CLASS_MAPPING extension points multifunctional registers into.
bw2calc — runs LCA calculations against the allocated, single-output read-only processes this package produces (via the bw_processing datapackage bw2data writes).
bw2io — importers (e.g. from ecoinvent/SimaPro) that commonly write multi-output processes into a multifunctional-backed database for allocation.
