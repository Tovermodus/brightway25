Note from the brightway25 code map: this page is generated straight from multifunctional's installed docstrings, so a gotcha worth knowing isn't stated here. MultifunctionalDatabase.process() runs allocation unconditionally on every multifunctional node whenever the database is written — so default_allocation (passed to db.register(default_allocation=...), or set per-node) must already be resolvable before the very first write(), or it raises ValueError: Can't find `default_allocation` in input arguments, or process/database metadata. There's no silent fallback strategy. See the multifunctional allocation tutorial for a full worked example that hits this deliberately, and the multifunctional module map for how allocation fits into the rest of the package.
