randonneur_data

A registry/data-store of pre-built randonneur migration datapackages — JSON files describing create/replace/update/delete/disaggregate operations between named data sources (e.g. ecoinvent version-to-version, SimaPro → ecoinvent, Agribalyse → ecoinvent). It holds the data; the separate randonneur package is the engine that applies it.

Key files

FileRole
__init__.pyEntire package logic: the Registry class, DEFAULT_DATA_DIR, DATA_LABELS, __version__.
data/registry.jsonIndex of every bundled datapackage: a JSON dict of {dataset_name: metadata}, 57 entries. Metadata includes description, source_id, target_id, graph_context, contributors, licenses, version, filename, compression, and a mapping schema block.
data/*.jsonUncompressed datapackage files (used when raw JSON is small, < ~200 KB).
data/*.gzGzip-compressed datapackage files (larger datasets) — decompressed transparently by Registry.get_file().

Dataset names registered in data/registry.json (not file paths) fall into a few families:

simapro-2025-ecoinvent-3-contexts

SimaPro 2025 → ecoinvent 3 context mapping.

agribalyse-3.1.1-restore-simapro-ecoinvent-names

Agribalyse → ecoinvent name restoration.

Agrifootprint → ecoinvent biosphere mapping.

generic-brightway-unit-conversions

Generic Brightway unit conversion table.

standard-units-harmonization

Standard units harmonization mapping.

Each entry's graph_context field says what graph objects the datapackage modifies (typically ["edges"] for biosphere/flow mappings, ["nodes"] for activity/product renames).

The Registry class

Registry (defined in __init__.py) is a collections.abc.MutableMapping keyed by dataset name, backed directly by registry.json on disk — every read or write reloads/rewrites the whole file, there is no in-memory cache.

MemberDescription
Registry(filepath: Optional[Path] = None)Constructor. filepath overrides which registry JSON to use; defaults to DEFAULT_DATA_DIR / "registry.json". self.data_dir becomes filepath.parent, and datapackage files are resolved relative to it.
DEFAULT_DATA_DIRModule-level Path to the bundled data/ directory next to __init__.py.
Dict protocolregistry[name], registry[name] = metadata, del registry[name], name in registry, len(registry), iter(registry), plus inherited .keys()/.values()/.items() — all operate on metadata dicts, not full datapackage contents.
get_file(label)Loads and returns the full datapackage JSON for dataset label, decompressing gzip/lzma transparently based on the registry metadata's compression field. The main way to get actual migration data.
schema(label)Shortcut for get_file(label)["mapping"] — the source/target field-expression schema.
sample(label, number=2, verb=None)Returns a random sample of number transformation entries per verb (create/replace/update/delete/disaggregate), for quick inspection.
add_file(filepath, replace=False)Validates and copies an external datapackage JSON into data_dir (gzip-compressing if > 200 KB), then registers its metadata. Returns the new path.
validate_file(filepath)Validates a datapackage's contributors, mapping, and per-verb data against randonneur.validation schemas. Raises ImportError if randonneur isn't installed — the only cross-dependency in this package.
__str__ / __repr__Human-readable summaries — print(registry) lists every registered file with description, source/target ids, authors, version, licenses.

Typical usage

from randonneur_data import Registry

registry = Registry()  # uses bundled data/registry.json

# list available migration datasets
list(registry)[:5]
# ['simapro-ecoinvent-3.10-cutoff', 'simapro-ecoinvent-3.8-cutoff', ...]

# inspect one dataset's metadata (source/target ids, graph_context, licenses, ...)
meta = registry["ecoinvent-3.9.1-cutoff-ecoinvent-3.10-cutoff"]
print(meta["source_id"], "->", meta["target_id"])

# pull the field-expression schema without loading the full datapackage
registry.schema("ecoinvent-3.9.1-cutoff-ecoinvent-3.10-cutoff")

# load the full datapackage (decompresses .gz automatically) to hand
# to randonneur's migration engine
data = registry.get_file("ecoinvent-3.9.1-cutoff-ecoinvent-3.10-cutoff")
data.keys()  # e.g. dict_keys(['update', 'mapping', 'name', ...])

Where to look

How do I find what migration datasets are available?
Instantiate Registry() and iterate it, or print(registry) for the formatted summary — each key is a dataset name from data/registry.json.
Full generated API reference →

Auto-generated from installed docstrings via pdoc (see docs/generate_api_docs.py) — every public class, function and module in randonneur_data, always in sync with what is installed. Not committed to git; built fresh on every deploy.

How do I get the actual migration data for a dataset?
Registry().get_file(name) in __init__.py — handles gzip/lzma decompression transparently.
How do I know what fields/expressions a datapackage's source and target use?
Registry().schema(name), or read the mapping key directly from get_file(name) or the registry metadata.
How do I add a new bundled datapackage?
Registry.add_file() in __init__.py — note it requires randonneur installed (it calls validate_file(), which imports randonneur.validation).
Where are the actual JSON/gz data files?
randonneur_data/data/, next to __init__.py — registry.json is the index, everything else is one file per dataset.
