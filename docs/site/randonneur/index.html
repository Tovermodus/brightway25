randonneur

A generic, data-driven engine for migrating/patching a graph of nodes and edges — JSON-diff-like transformations (create/replace/update/ delete/disaggregate) applied to arbitrary dict-shaped data. It knows nothing about LCA semantics; the actual migration data (e.g. renamed activities or biosphere flows) is supplied separately, typically by randonneur_data.

Typical usage

from randonneur import migrate_edges, migrate_nodes, MigrationConfig

graph = [
    {
        "name": "some process",
        "edges": [{"name": "carbon dioxide", "amount": 1.0}],
    }
]

# Rename a biosphere flow, changing its unit/context along the way
migrations = {
    "update": [
        {
            "source": {"name": "carbon dioxide"},
            "target": {"name": "Carbon dioxide, fossil", "context": "air"},
        }
    ]
}

migrate_edges(graph, migrations, config=MigrationConfig(verbose=True))

# Or, apply a pre-built dataset shipped by randonneur_data
migrate_nodes_with_stored_data(
    graph=graph,
    label="some-dataset-label",
)

Where to look

How do I apply a set of migrations to my data?

migrate_nodes(graph, migrations, config=None) and migrate_edges(graph, migrations, config=None) in nodes.py / edges.py. Both mutate graph in place and return it.

How do I load a pre-built migration dataset instead of writing the migrations dict myself?

migrate_edges_with_stored_data() / migrate_nodes_with_stored_data() in edges.py / nodes.py — thin wrappers around randonneur_data.Registry(...).get_file(label) that verify the data's graph_context matches (raising errors.WrongGraphContext otherwise) before delegating to migrate_edges/migrate_nodes.

Why didn't my transformation match / apply?

Matching is done by FlexibleLookupDict in utils.py, indexed by (field, value) pairs from each transformation's source. A missed match raises (and silently swallows) a KeyError. Check MigrationConfig.fields, MigrationConfig.case_sensitive (default False), and MigrationConfig.mapping — see the docstring in config.py.

What do the five transformation verbs do?

create (append), replace/update (same implementation for edges — overwrite matched fields, rescale amount if a conversion factor/allocation is present), delete (remove matched), and disaggregate (split one edge into several via a targets list, edge-only). See edge_functions.py and node_functions.py — node-level replace/disaggregate raise NotImplementedError.

How do I build and validate a new migration-data JSON file?

Datapackage in datapackage.py: construct with metadata + a mapping_source/mapping_target (see MappingConstants in constants.py for ready-made ones), call .add_data(verb, data) per verb (validated by validation.validate_data_for_verb, raising errors.UnmappedData on a key mismatch), then .to_json(filepath).

Can non-developers author migration data without writing JSON?

Yes — create_excel_template() / read_excel_template() in templates.py generate/parse an Excel workbook covering the same verb structure.
