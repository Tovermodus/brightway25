Note from the brightway25 code map: this page is generated straight from bw_migrations's installed docstrings, so a couple of things worth knowing aren't stated here. First, the commented-out create_core_migrations() block at the bottom of __init__.py references a Migration class and several get_*_migration_data() helper functions that do not exist anywhere in this installed package — treat it as dead/aspirational code, not a real API. Second, migrate_data(data, migration) is a pass-through, not a filter: a row whose lookup key has no match in the migration is caught internally on a KeyError and yielded completely unchanged, so applying a migration never drops or errors on unmapped rows. See the migrating data with bw_migrations tutorial for a full worked example (rename + rescale + fan-out, and the no-match case), and the bw_migrations module map for how this fits into the rest of the import stack.
