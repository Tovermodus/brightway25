bw_migrations

Curated cross-dataset data migrations — e.g. EXIOBASE↔ecoinvent biosphere flow name/unit mapping — applied to raw, in-memory data dicts before they're written into a bw2data database. Used as a building block during import.

Version 0.2. This is a small, dependency-light utility package: it does not read or write a Brightway project itself (aside from one optional lookup join) — it transforms plain Python data structures according to a JSON lookup table. It's typically called from import strategies such as those in bw2io.

Main functions / entry points

get_migration(location)

Resolves a migration into a loaded dict. location may be a Mapping (returned as-is), a Path/string pointing at an existing JSON file, or a bare string name (e.g. "exiobase-3-ecoinvent-3.6") matched against the bundled files in bw_migrations/data/. Raises ValueError if nothing matches.

migrate_data(data, migration)

Generator. Builds a lookup keyed by tuple(row[field] for field in migration["fields"]) and, for each row in data, yields it unchanged if there's no match, or yields it modified (via modify_object) if there is. A replacement that is a list of dicts fans one input row out into several output rows (deep-copied) — this is how one source flow splits into multiple target flows.

load_and_clean_exiobase_3_ecoinvent_36_migration(ecoinvent_biosphere_name=None, explode=False)

Loads the bundled EXIOBASE 3 → ecoinvent 3.6 migration and reshapes it into a pandas DataFrame with columns exiobase name, exiobase compartment, ecoinvent name, ecoinvent unit, ecoinvent categories, multiplier, disaggregation, and a combined factor column. Pass ecoinvent_biosphere_name to left-merge against a real bw2data.Database and attach a biosphere index (id) column; pass explode=True to keep one row per replacement instead of the default form grouped by (exiobase name, exiobase compartment).

Typical usage

from bw_migrations import get_migration, migrate_data

# 1. Apply a bundled migration to a list of biosphere flow dicts
migration = get_migration("exiobase-3-ecoinvent-3.6")
raw_flows = [
    {"name": "1,3 Butadiene", "categories": "air", "amount": 0.002},
    {"name": "some flow with no mapping", "categories": "water", "amount": 1.0},
]
cleaned = list(migrate_data(raw_flows, migration))
# rows with a match get renamed/rescaled fields merged in;
# rows with no match pass through unchanged

# 2. Get the same mapping as a tidy pandas DataFrame, joined
#    against a real ecoinvent biosphere database for flow ids
from bw_migrations import load_and_clean_exiobase_3_ecoinvent_36_migration

df = load_and_clean_exiobase_3_ecoinvent_36_migration(
    ecoinvent_biosphere_name="biosphere3",
    explode=True,
)

Where to look

I need to load a bundled or custom migration file — where?

strategies.get_migration(). It accepts an in-memory Mapping, a path to any JSON file, or a bare name resolved against strategies.DATA_DIR (bw_migrations/data/).

How do multiplier/disaggregation rescaling actually work?

strategies.modify_object() computes scale = __disaggregation__ * __multiplier__ from the replacement dict and, if not 1, calls utils.rescale_object(), which knows how to rescale amount/loc/scale/minimum/maximum/formula correctly per stats_arrays uncertainty type.

What does the raw migration JSON look like?

Open data/exiobase-3-ecoinvent-3.6.json directly — top-level keys are fields, data, license, version, contributors, missing flows, comment. data is a list of [key, replacement] pairs where replacement is a dict or list of dicts.

Can I register a new named migration so get_migration("my-name") finds it?

Not via any API in this version — there's no writer/save function. Drop a correctly-shaped .json file into bw_migrations/data/ (or just pass a file path/dict directly to get_migration/migrate_data). The commented-out create_core_migrations() block at the bottom of __init__.py references a Migration class that does not exist in this package — ignore it.

Does this package touch a Brightway project database?

Only optionally, and only for reads: load_and_clean_exiobase_3_ecoinvent_36_migration() can left-merge against a bw2data.Database to look up flow ids. get_migration/migrate_data/modify_object operate purely on in-memory dicts and never write anything.

→ bw2io — the main import layer; strategies here call into bw_migrations to rename/rescale flows before writing to bw2data. → randonneur — a similar but simpler migration-application pattern, also used to feed cleaned data into import pipelines that write to bw2data.
