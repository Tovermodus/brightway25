bw2data

The core persistent data model for Brightway: projects, databases, activities/exchanges, LCIA methods and parameters — the SQLite-backed layer every other Brightway package reads or writes through.

Installed at .venv/lib/python3.11/site-packages/bw2data/, version 4.7 (PyPI bw2data>=4.4.2). Backed by SQLite via peewee. Upstream repo: brightway-lca/bw2data.

Where to look

What's the difference between a "process", a "product", and a "chimaera" node?

Verified in configuration.py (MatrixLabels) and utils.py set_correct_process_type(). There are three LCI node type values (labels.lci_node_types):

  • "process" (labels.process_node_default) — a pure process node with no product data of its own. It links to a separate "product" node via a production edge (type="production") whose input points at that other node.
  • "product" (labels.product_node_default) — a pure reference-product node: holds the product's own name/unit/categories/properties, separate from the process that makes it.
  • "processwithreferenceproduct" (labels.chimaera_node_default, informally called a chimaera node in the code and docstrings) — a single node that carries both the process data and the reference product data together. Its production exchange is self-referential: input equals the node's own (database, code) key. Every example on the Examples page that gives an activity a self-referencing production exchange (e.g. steel.new_exchange(input=steel.key, ..., type="production"), as in Examples 1 and 3) is building a chimaera-shaped node — the product's name, unit and other properties just live directly on that one node, and both the process's and the reference product's information turn up together when you look it up or search for it. Example 2 builds the same inventory both ways, side by side, and prints the resulting type of each node.

Database.write() (backends/base.py:675) auto-classifies datasets via utils.py set_correct_process_type() (utils.py:420): a dataset with an explicit self-referencing exchange, or with no explicit production edge at all (implicit self-production), is set to the chimaera type (labels.chimaera_node_default, line ~436/446). This auto-classification only runs through bulk write() — activities built one-by-one via new_activity() / .save() (as in the Examples page) keep whatever type you pass, or none, unless you set it yourself.

On the import side, bw2io.strategies.products separate_processes_from_products() does the reverse: given chimaera/process datasets, it splits each into a separate process node and a new product node (using the "reference product" field for the product's name if present), and relinks the production edge between them. See the bw2io module map.

How is an activity stored on disk?

backends/schema.py (ActivityDataset, ExchangeDataset peewee models — the SQL table schema) together with backends/proxies.py (Activity.__getitem__ / .save() for the in-memory proxy view).

How does bw2data hand off to bw2calc?

data_store.py ProcessedDataStore.process() and its override backends/base.py SQLiteBackend.process() (line ~1022) — both write a bw_processing datapackage on disk that bw2calc.LCA loads directly.

How do projects isolate data?

project.py — ProjectManager (the projects singleton, switches the active SQLite DB + data dir) and ProjectDataset; mutating methods are wrapped with the writable_project decorator.

How are LCIA methods represented?

method.py Method(ImpactAssessmentDataStore), registered in meta.py's methods singleton.

How do parameterized / formula-driven exchanges work?

parameters.py — ProjectParameter, DatabaseParameter, ActivityParameter, ParameterizedExchange, orchestrated by ParameterManager; formulas are evaluated via the separate bw2parameters package.

How do I look up a single activity, or resolve its numeric id?

utils.py get_node(**kwargs) / get_activity(key=None, **kwargs); backends/schema.py get_id(key) for the integer id used internally and by bw_processing datapackages.

Related modules

bw2calc — runs LCA calculations against the bw_processing datapackages that bw2data's .process() writes.
bw_processing — the datapackage format bw2data serializes processed matrices into, and bw2calc reads.
bw2io — importers/exporters that write activities and methods into bw2data databases.

bw2analyzer — analysis/reporting tools built on top of bw2data activities and bw2calc results.
bw2parameters — the formula-interpolation engine used by bw2data.parameters.
